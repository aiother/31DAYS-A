# 双方协作规范

## 职责与项目范围

- Codex：底层逻辑、玩法、状态、数据、存档逻辑及相应测试；负责核查跨模块接口和集成结果。
- Claude：视觉呈现、Godot UI、交互反馈、布局及相关 UI 测试。可以阅读整个项目；修改范围由每次任务明确指定。
- UI 不一定全部位于 game/ui/；先调查实际代码归属，不因文件名或职责划分批量迁移现有实现。
- 跨职责文件、公共接口、输入配置和 project.godot 的修改先提出影响和方案，由用户明确同意后执行。
- 协作资料统一存放 codexandclaude/；游戏代码、资源和游戏测试继续放在原工程目录。

## 冻结与现有工作保护

- T0–T8 冻结范围保持不变，不擅自增加角色、系统、正式美术或玩法；冲突与缺口报告给用户裁决。
- 策划依据位于 Words/，技术实施记录位于 game/docs/technical_baseline.md；不能把实施记录当成扩大冻结范围的授权。
- 操作前查看 Git 状态与差异。现有未提交变更必须保留，不自动暂存、提交、覆盖、清理或回滚他人工作。
- 新建 worktree 以明确提交为基线；主工作目录未提交内容不会自动进入新 worktree。用户确认前不把这些内容复制到分支。
- 写代码前为双方建立独立分支和 worktree，并在任务中记录目录、基线提交、可修改文件和测试；共享 Git 历史不等于系统权限隔离。
- 同一文件只分配给一方。出现重叠或意外改动先停止，协调归属后再继续。

## 人工执行与许可

- 当前仅人工触发：用户在两个官方客户端分别下达任务、确认必要操作、转交结果。
- Claude 保留 Manual 手动审批；不得自行启用自动授权、跳过权限、后台循环或调用另一个 Agent。
- 不提取、复制或互传订阅令牌，不配置非官方代理，不规避 Anthropic 的地区、账户或用量限制。
- CLI 自动化、服务条款和 API 许可留到人工试点完成后单独核对；不得把订阅可登录理解成任意自动化已获许可。API 用量与订阅分别确认计费。
- 不自行安装依赖、推送远程、发布、删除工作区或修改全局 Git/账号配置。

## 每次交付

先报告任务目标、工作区、基线、允许修改文件和接口；完成后报告实际文件、验证命令、结果、未验证内容与提交哈希。

按根目录 Agents.md：每次改动必须编写或更新相关测试，交付前相关测试和验证全部通过，并创建对应 Git commit。只提交自己此次明确负责的文件，不使用整仓批量暂存。只读审查没有文件改动，不创建空提交。

文档检查不能代替 Godot 运行验证。涉及游戏代码时，按改动选择专项测试，再执行必要的工程回归；UI 另需实际运行、输入、暂停及缩放等相关验收。失败不能标作通过，原有问题与新引入问题分别报告。

双方先提交各自分支，由协调者审查差异、测试和冻结符合性，再在集成分支合并和复测；不自动合并或推送。
