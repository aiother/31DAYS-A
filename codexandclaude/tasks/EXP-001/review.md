## 阻断意见

### R1：A-016 的视觉加速暂停了真实预算，最终战期间第3日钟表完全不走

`hud_state.gd:80` 在 `accelerate_left > 0` 时直接 return，2.5 秒加速演出期间 `final_remaining` 完全不扣；进入 final_active 分支后只扣 final_remaining，又在扣 day_remaining 前 return。因此这不是单纯的显示插值：按 O 后实际计时多出2.5秒，最终战中下角时刻也冻结。独立探针 `start_final(1500); tick(2.5); tick(1)` 得到最终预算依次900、899，第3日余额始终1500。

依据任务卡状态6、A-016及 T5.4 §6.4，视觉上从25分钟加速到15分钟不能改变真实计时规则。“多出的时间不被消耗”指不在开战时把第3日余额强制截为900，并非自然计时停止。请让视觉插值与真实预算独立更新；正常时间流速下，两项真实余额都应随经过时间扣除，暂停时按统一暂停语义处理。增加加速过程、加速结束后以及不足15分钟分支的确定性 tick 断言；现有冒烟测试断言 `final_remaining == 900` 恰好固化了演出停表行为，需一并修订。无需接入正式会话。

### R2：方案三在余额为零时无法呈现 A-018 红闪

`variant_fracture.gd:39–40` 在已将 DENY 混入 color 后，以灰色无条件覆盖 `balance == 0` 的结果；后面的基础容量环只变化白色透明度和线宽，仍不是红色。操作：选3，余额消耗至0，按 E；`deny_left` 已为0.9，但光团保持灰色。失败恢复不会改变余额，因此整个提示期间都不红。交付的高压截图设为-4，避开了这个边界。

请使零余额的空容器也响应同样的红闪，并补充零余额/正数不足/负数不足三种状态检查或可复核画面证据。此项是任务卡状态3、A-018的必需反馈，不是方案三已经声明的形状、位置等视觉偏离。

### R3：方案三在零珍珠时隐藏当前攻击范围

`variant_fracture.gd:58–59` 将范围文本放在 `if state.pearls > 0` 下。初始状态和按 Z 减至0时，“范围100%”消失；方案一、二仍显示，方案三也没有另一个能明确读出当前范围的标识。G-02 要求珍珠数量与当前攻击范围，不仅是强化后显示，任务卡要求每个方案可演示。README 没有声明省略这一必需信息。

请保留零珍珠时的当前范围显示，并为0→1→0的操作路径补回归检查；可以继续用百分比，与正式灰盒 HUD 一致，不要求改成像素数。

### R4：固定扣1的闪避模型漏掉正数余额下的 A-018 不足状态

`hud_state.gd:131–138` 每次闪避只判断 `balance < 1` 并扣1；没有 T3 §4 的连续闪避1/2/3成本。独立探针从余额2连续调用两次闪避，得到余额0、deny=0；按正式规则第二次成本2，余额1已不足，应透支至-1并提示。README 只声明成长步长、时刻映射等假设，没有声明闪避成本的改动，用户容易因此误判提示触发条件。“不显示连续闪避次数”不等于内部成本固定为1。

请用最小模拟状态保留连续成本和1.3秒重置，或提供明确的当前动作成本切换以忠实演示成本1/2/3对应的不足边界，不显示连闪计数；不要求接入真实角色物理。补充余额等于成本/小于成本但仍为正数、连续及重置路径的测试，并同步 README 操作说明。
