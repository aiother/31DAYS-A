# EXP-003：主界面与存档选择探索原型

状态：已交付，待用户试玩挑选与 Codex 审查（2026-10-21）｜级别：M｜实现：Claude｜审查：Codex
工作区：worktrees/claude｜基线：本任务卡合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：无（与 UI-003、SYS-007 可并行）

## 目标

为待办 BL-040（主界面）与 BL-041（存档选择）做可操作原型，各给 2～3 个方案，由用户试玩挑选；同时确定“返回标题”的流程。选定后第五批正式实现主界面、存档选择，以及依赖“返回标题”的死亡、结束、超时界面。

## 依据

- 待办 BL-040、BL-041；T7-A“游戏主界面”“存档选择”；T7-D“返回主菜单”；T7-E1、T7-F。
- 裁决 A-013（已通关存档不能再进入，提示“游戏已通关”）、A-011、A-014（结束、超时、死亡界面都有“返回标题”）。
- SYS-004 审查记录的建议：已通关槽的“继续”可直接做成已通关样式。
- 协作规范 §3.3：新增或明显改变交互的界面先做可操作原型，用户挑选后再正式实现。
- 视觉沿用 EXP-002 样张二与 UI-001 样式模块。

## 要求

1. **主界面**（2～3 个方案）：标题位于中上方、约占画面 1/3；菜单为新游戏、继续游戏（没有任何存档时不显示）、设置、退出游戏；新游戏需确认。背景按 T7“朦胧滤镜与打光的颓废背景”：本版没有正式美术，各方案可用不同的程序化做法（例如黄昏远景剪影、模糊后的游戏画面、纸面与光斑），由用户比较。
2. **存档选择**（2～3 个方案）：T7 要求“横向书签式”；每个存档显示标题、游戏时长、角色属性、最后检查点；新游戏只覆盖所选槽；已通关的槽有明确样式，选择时提示“游戏已通关”（A-013）；空槽与不可读取的槽也要有样式。
3. **流程**：启动 → 主界面 → 继续游戏 / 新游戏 → 存档选择 → 进入游戏；以及暂停、死亡、结束、超时时“返回标题”回到主界面。原型里用模拟数据演示，按键说明随原型给出。
4. 原型只放在 `game/prototypes/EXP-003/`，不改正式场景、共享脚本、`project.godot`、输入映射或存档；能独立启动，附截图。
