## 问题清单（由 ENV-008 修订）

### R1 / P1：授权识别对“中文说明后缀”整体漏检（任务卡指定的审查重点）

`license_errors` 为识别连写、下划线等写法，把授权栏压成只含 `[a-z0-9]` 的 `compact` 串再比较，**非 ASCII 字符全部被丢掉**。结果是在合法的 CC-BY 写法后面加任何中文说明，都被当成纯 `CC-BY-4.0` 放行，包括明确的限制：

| 授权栏 | `license_errors` 结果 |
| --- | --- |
| `CC-BY-4.0（不可商用）` | 通过（应拒绝） |
| `CC-BY 4.0 仅限个人学习` | 通过（应拒绝） |
| `CC-BY 4.0（非商用）` | 通过（应拒绝；列表里只有“非商业”，没有“非商用”） |
| `CC BY 4.0 不得商用` | 通过（应拒绝） |
| `CC-BY 4.0 （禁止二次创作）` | 通过（应拒绝） |
| `CC-BY-4.0（禁止商用）` | 拒绝（只因恰好在关键词列表里） |

同一机制还让 `CC-BY-4.0 (Candy)`、`CC-BY-4.0 Fonds` 被误报为“禁止 NC/ND 授权”（`compact` 里含 `nd`），提示与真实原因不符。这正是任务卡写明的“授权识别是否有漏网写法”，且 T6 第 2.1 节要求不用 NC、ND。关键词黑名单天然不可能穷尽中文写法。

**建议修法**：授权栏只允许精确格式，不再依赖黑名单——NFKC 归一并 `casefold` 后，必须整体匹配 `CC0`、`OFL-1.1`、`免版税可商用`、`AI 生成`、`自制` 或 `^cc[ _-]?by[ _-]?\d(\.\d)?$`（之后限定词一律写进“备注”列）；其余写法一律“未知或不允许”。NC/ND 识别可保留，只用来给出更清楚的失败原因。测试补上表中前五行（必须失败）与 `CC-BY-4.0 (Candy)`（应给出“未知或不允许”而不是 NC/ND）。

## 非阻断建议

- N1：`CC-BY`（无版本）、`CC BY 3`、`CC0-1.0` 现在报“未知或不允许”，提示可以写明“须写版本号，如 CC-BY-4.0”。
- N2：白名单是封闭的：`CC-BY-SA`、MIT、Apache-2.0 等都会被拒绝。T6 只规定“优先 CC0 / 免版税可商用，不用 NC、ND”，没有明确允许或禁止 SA 与其他开源许可。保守是合理的，但应在 `CREDITS.md` 的“自动检查”一节写一句“白名单之外的授权须先经用户批准再扩充”，避免以后被误当成缺陷。
