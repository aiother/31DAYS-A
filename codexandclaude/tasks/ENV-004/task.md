# ENV-004：引擎测试分散登记

状态：草案（2026-10-20 起草，待用户批准）｜级别：M（工具）｜实现：Codex｜审查：Claude
工作区：worktrees/codex｜基线：本任务卡合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：无

## 目标

完成待办 BL-103：把引擎专项测试从 `scripts/verify_game.py` 中的单一固定列表改为“每个套件独立登记、入口汇总”，消除并行任务都要改同一个列表和同一个固定总数这一冲突点，为 M2 多个 UI 任务并行做准备。

## 依据

- 待办 BL-103（来源：SYS-001、SYS-002 依赖安排；Codex 阶段复盘意见）。
- 路线图第 3 节工具线、第 5 节第一批建议：本任务先于 SYS-004 与大批 UI 任务。

## 现状（起草时核对 master@b572c7e）

- `scripts/verify_game.py:11` 起的 `TESTS` 列表登记 73 个套件，每项为（名称、`res://tests/...gd` 路径、结果标记前缀）。
- 同文件 `execute()` 按文件名硬编码哪些套件用固定 60 帧、超时 600 秒或 180 秒，这是第二个需要并行修改的地方。
- `tests/test_verification_runner.py:41` 断言 `len(verifier.TESTS) == 73`，任何新增套件都要同时改这个数字。
- `codexandclaude/tools/run_checks.py` 通过导入 `verifier.TESTS` 统计 G2 预期数与 `focused --godot-script` 的合法路径。

## 要求

1. 新增或删除一个套件时，只需改该套件自己的文件（或与它一一对应的登记文件），不必改公共列表或固定总数。
2. 汇总入口校验：路径唯一、文件存在、结果标记唯一；`game/tests/` 下每个 `test_*.gd` 要么已登记，要么在显式排除清单中注明理由（漏登即失败）。
3. 实际执行的套件集合必须与登记集合完全一致，缺一个或多一个都失败。
4. **不得**只把固定总数改成注册表自身长度：漏登时两边会一起“通过”。完整性要靠第 2 条的文件对照，而不是数自己。
5. 固定帧率与超时等运行参数随套件登记，不再在 `execute()` 中按文件名硬编码。
6. 迁移前后执行的套件集合、名称、结果标记与运行参数逐项相同（交付记录给出对照）。
7. `run_checks.py` 的 G2 预期数、`focused --godot-script` 路径校验继续可用；若接口变化，同步更新。

## 做法（已选甲）

| 做法 | 说明 | 取舍 |
| --- | --- | --- |
| **甲：测试文件头部元数据（采用）** | 每个 `test_*.gd` 顶部用固定格式注释写名称、结果标记、运行参数；入口扫描目录生成登记表 | 一个套件只有一个文件，最不容易漏；需要改 73 个测试文件的头部（只加注释，不改逻辑） |
| 乙：逐套件登记文件 | 例如 `game/tests/suites/<套件>.json` 或 `scripts/suites/` 下逐个小文件 | 不碰测试文件；每个套件两份文件，需要校验一一对应 |

起草方与实现方（Codex 2026-10-20 卡片意见）都推荐甲：单套件单文件更不容易漏登。迁移时逐项核对名称、结果标记、固定帧率与超时参数。

因为甲会修改全部现有测试文件的头部，本任务合入前，其他任务不要修改 `game/tests/test_*.gd`（SYS-004 因此排在本任务之后）。

## 允许修改的文件

- `scripts/verify_game.py`。
- `game/tests/test_*.gd`：只添加头部元数据注释，不改测试逻辑。
- `tests/test_verification_runner.py`：改为验证新的登记与完整性规则。
- `codexandclaude/tools/run_checks.py` 及 `codexandclaude/tests/` 中相关测试：仅在接口变化时同步。
- `codexandclaude/env.md`：写明新增套件如何登记。
- `codexandclaude/tasks/ENV-004/task.md`（只更新首部状态）、`delivery.md`（新增）。

## 完成标准

1. 满足“要求”1～7。
2. 交付记录给出迁移前后的套件对照（名称、路径、标记、运行参数），73 个套件一个不少。
3. 变异检查（实现者自测，审查者复现）均失败：新增一个未登记的 `test_*.gd`；两个套件登记同一路径；登记指向不存在的文件；删除一个套件的登记；执行集合缺一个套件。
4. G2 与 G3 全部通过，引擎套件数与迁移前一致。
