# SYS-005：UI 数据接口

状态：进行中（2026-10-21，从已合入规划的 master 开工）｜级别：M｜实现：Codex｜审查：Claude
工作区：worktrees/codex｜基线：本任务卡合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：无

## 目标

完成待办 BL-111：为正式 HUD（UI-002）提供它需要、而现有代码没有的系统信号与只读状态。**只加信号与查询，不改任何游戏规则、数值或存档格式。**

## 依据

- 待办 BL-111；EXP-001 交付记录（方案四）与 EXP-002 交付记录（样张二）中 HUD 需要表现的状态。
- 裁决 A-016（最终战倒计时显示）、A-018（尝试恢复或闪避而可能性不足时容器发红闪烁）。
- T3 §4（可能性、恢复与连续闪避成本）；T4（自然计时与日期）。

## 现状（起草时核对 master@20c73b7）

- 现有信号只有 `PlayerPossibility.balance_changed`、`PlayerLife.health_changed / damaged / died` 等；`LifeUI._process()` 每帧轮询读取文字 HUD 所需数值。
- `PlayerPossibility.try_heal()` 在可能性不足时直接返回 false，没有任何通知；`try_dodge()` 在不足时会透支（设置 `poor_dodge`），也没有专门信号。
- 日期播报在 `FinalBattleSession._announce_day()` 内部；没有面向 UI 的换日信号、换日前3分钟状态或最终战加速演出状态的统一查询。

## 要求

1. **可能性不足**：玩家尝试恢复而可能性不足、或闪避时本次成本超过余额（透支闪避），各发出一次可区分种类的信号（例如 `shortfall(kind)`，kind 为恢复/闪避）。因其他原因（硬直、空中、满血等）无法恢复时不发。
2. **可能性获得**：获得可能性时发出带数量与来源世界坐标的信号（来源未知时给出合理默认，如玩家位置），供光效飞入。现有 `balance_changed` 保留。
3. **日期与计时**：提供会话层的信号或查询——日期变化（新日期）、是否处于换日前3分钟及剩余秒数、当前日内进度（0～1）、是否最终战、最终战真实剩余预算、开战时第3日余额（用于判断是否走 A-016 的加速演出）。数据来源用现有 `DayClock`、`FinalClock` 与会话状态，不另造计时。
4. 读档、死亡重载、换槽、暂停后，查询结果与信号行为正确（不重复发出过期的换日信号，不漏发）。
5. 现有 `LifeUI` 文字 HUD 行为不变；不修改正式 UI 文件（UI 由 UI-002 接入）。

- `game/docs/` 中相关实现说明。
- `codexandclaude/tasks/SYS-005/task.md`（只更新首部状态）、`delivery.md`（新增）。

## 完成标准

1. 要求 1～5 各有自动测试，并在交付记录中逐条对应；测试使用真实输入或真实会话路径，不只调用新函数本身。
2. 不足信号的边界：余额等于成本不发；连续闪避第二次成本 2、余额 1 时发闪避不足；余额不足 3 尝试恢复时发恢复不足；满血不发。
3. 换日信号在自然换日、跨日读档、死亡重载三种路径下各只发一次。
4. 现有全部测试通过，`LifeUI` 文字 HUD 相关测试不改。
5. 审查时变异检查：去掉某个发出点后，对应断言失败。
