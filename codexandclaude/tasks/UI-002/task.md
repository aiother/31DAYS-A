# UI-002：正式 HUD 与时间显示

状态：已交付，待 Codex 审查（2026-10-21；开工时用户批准小幅扩范围，见交付记录）｜级别：L｜实现：Claude｜审查：Codex

## 目标

完成待办 BL-042（HUD 正式化）与 BL-043（时间显示）：用用户选定的方案（交互：EXP-001 方案四；视觉：EXP-002 样张二）替换现在的灰盒文字 HUD，接入真实游戏数据。

## 依据

- EXP-001 交付记录“G4 第2轮：用户选定方案四”；EXP-002 交付记录“G4 用户选定”。
- 待办 BL-042、BL-043；T7-B、T7-F；裁决 A-015（由方案四代替：日常地平线时刻，完整时间放暂停菜单）、A-016、A-018；T7 核对表 G-02（珍珠与攻击范围）。
- UI-001 的样式模块与主题；SYS-005 的信号与查询。

## 要求

1. **徽记 HUD**：生命只显示现有数量（朱红碎片），可能性环形格，成长上限为外圈附加段，透支从顶部逆时针反向变暗红，珍珠与“范围 xx%”纸签（G-02），获得时光点从来源位置飞入环（SYS-005 获得信号）。
2. **可能性不足**：收到 SYS-005 的不足信号时环发红闪烁（A-018）；可能性低于0时，HUD 之下的游戏画面加失真滤镜，强度随透支加深，HUD 本身不失真。
3. **最后1点生命**：画面边缘朱红脉动。
4. **时间**：底部地平线与太阳、太阳上方时刻纸签、右下“第N日 · 末日前N天”；换日时中上部纸签；换日前3分钟右下提示；最终战倒计时在中上部——开战时余额超过15分钟走加速演出（只是画面，真实预算照常流逝），不足15分钟直接显示真实剩余并用朱红警示（A-016）。
5. **黄昏随天数加深**，最终战光晕减弱 30%（UI-001 已实现计算，本任务接真实数据）。
6. **手写字体**：HUD 文字使用 UI-001 主题中的霞鹜文楷。
7. 去掉旧文字 HUD 中被新 HUD 覆盖的行；暂停、死亡、存档槽等菜单维持灰盒不变（第四批处理）。旧 HUD 中的操作提示（如“K/B 滑步”“长按 L/Y 恢复”）是否保留由实现时提出，交用户决定。
8. 现有存档错误提示等与 HUD 共存的界面不重叠（沿用 `test_hud_layout.gd` 的防重叠要求，按新布局更新）。

1. 要求 1～8 有自动测试：使用真实玩家与会话（真实输入触发恢复不足、透支闪避、获得可能性、换日、最终战两种预算），断言 HUD 实际画出的内容与颜色（沿用 EXP-002 的“实际绘制记录”做法），关键色不随日期漂移。
