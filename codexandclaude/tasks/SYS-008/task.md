# SYS-008：主界面流程与存档摘要

状态：已批准（2026-10-21 用户批准）｜级别：M｜实现：Codex｜审查：Claude
工作区：worktrees/codex｜基线：本任务卡合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：无（UI-004、UI-005 依赖本任务）

## 目标

为正式主界面与存档选择（UI-004）以及死亡、结束、超时界面的“返回标题”（UI-005）提供系统部分：启动先进主界面、返回标题、按存档摘要显示各槽。**只做流程与只读数据，不做正式界面。**

## 依据

- 用户 2026-10-21 在 EXP-003 选定：主界面 A · 黄昏远景；存档选择为书签，并在每张书签上部加入当天的天空条。EXP-003 交付记录“G4 用户选定”与推荐流程（有存档时默认焦点在继续游戏；新游戏在选槽后确认）。
- 待办 BL-040、BL-041；T7-A“游戏主界面”“存档选择”、T7-D“返回主菜单”（允许随时返回，重进从最近检查点开始）、T7-E1；裁决 A-013、A-011、A-014。
- 现有 `CheckpointLab` 的选槽、读档重载（`checkpoint_reload`）、关窗保存与已通关拒绝（SYS-004）。

## 现状（起草时核对 master@beff144）

- 启动进入 `FinalBattleSession`，没有存档会话时 `CheckpointLab._ready()` 直接 `ui.show_slots()`（灰盒选槽）；没有主界面，也没有“返回标题”。
- 结束、超时面板的“存档槽 / 新游戏”回到灰盒选槽；死亡菜单只有“从检查点继续”和“退出游戏”。
- 槽快照已有 `day`、`day_remaining`/`day3_remaining`、`play_seconds`、`health`、`balance`、`maximum`、`checkpoint`、`events`；检查点配置有 `display_name`；珍珠数由事件推出。

## 要求

1. **启动进主界面**：没有存档会话时，会话发出“显示主界面”的请求（调用 UI 的 `show_title()`，UI-004 实现；UI-004 合入前回退为现有 `show_slots()`），而不是直接显示选槽。读档重载等已有路径不变。
2. **返回标题**：会话提供 `return_to_title()`：有会话时先按现有规则保存（失败则不离开，走现有错误提示），然后结束当前会话、回到“没有存档会话”的主界面状态；不残留上一槽的玩家状态、计时或敌人。重进该槽从最近检查点开始（T7-D，规则不变）。死亡菜单、V0.1 结束、最终战超时、第三日探索超时都能调用它。
3. **存档摘要**：提供只读查询 `slot_summaries()`，三个槽各返回：状态（进行中 / 已通关 / 空 / 无法读取）、第几日、当日进度（0～1，供天空条）、游戏时长（秒）、生命与上限、可能性与上限、珍珠数、最后检查点显示名。只读，不写盘、不修复、不改版本；读取失败的槽标为无法读取。另提供 `has_any_save()`（主界面决定是否显示“继续游戏”）。
4. **选槽入口不变**：继续游戏与新游戏仍经现有 `start_slot(slot, new_game)`，包括 A-013 已通关拒绝与覆盖规则；不新增存档字段。
5. 关窗、Esc、手柄 Back 在主界面与选槽界面的行为由 UI 决定，本任务不改输入映射。
