# UI-005：死亡、结束与超时界面正式化，暂停菜单返回标题

工作区：worktrees/claude｜基线：UI-004 合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：SYS-008（`return_to_title()`）、UI-004（主界面）

## 目标

完成待办 BL-050（死亡界面）与 BL-051（V0.1 结束、最终战超时、第三日探索超时界面），并在主界面存在后把暂停菜单的“存档槽”换成“返回标题”。

## 依据

- 裁决 A-014（死亡界面：从检查点继续、返回标题、设置、退出游戏）、A-011（最终战超时“未来已失”：游玩时长、重试、返回标题；探索超时保留独立反馈）；T7-A“死亡界面”“V0.1结束界面”“超时失败反馈”、T7-D“返回主菜单”；T7 核对表 G-03。
- 用户 2026-10-21：主界面做出来之前暂停菜单暂留“存档槽”（UI-003）；EXP-003 推荐流程“主界面完成后把存档槽换成返回标题”。
- EXP-003 的 `game_stub.gd` 演示；UI-003 的暂停菜单纸面与墨线按钮；SYS-008 的 `return_to_title()`。

## 要求

1. **死亡界面**（A-014）：画面边缘泛白后转暗（现有演出保留），纸面菜单：从检查点继续、返回标题、设置、退出游戏；说明行沿用现有规则文字（满生命复活、可能性减半向下取整、负数清零）。
2. **V0.1 结束**（临时标题“夕阳将至”）：游玩时长、返回标题；保留现有“存档槽 / 新游戏”能力由返回标题后的主界面提供。
3. **最终战超时**（临时标题“未来已失”）：游玩时长、重试（沿用现有可恢复预算与规则文字）、返回标题；原预算为 0 时只有返回标题。
4. **第三日探索超时**（G-03）：保留独立反馈与确认重试（返回当前检查点、恢复本日30分钟），加返回标题。
5. **暂停菜单**：“存档槽”换成“返回标题”（需确认：“保存并返回标题？下次从最近的检查点继续”）。
6. 所有“返回标题”都经 SYS-008 的 `return_to_title()`；保存失败时不离开并显示错误。
