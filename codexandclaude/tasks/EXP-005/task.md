# EXP-005：战斗反馈特效探索原型

状态：待审查（2026-10-23 交付；用户挑选待进行；原 2026-10-23 用户批准）｜级别：M｜实现：Claude｜审查：Codex
工作区：worktrees/claude｜基线：本任务卡合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：无（不需要外部素材；正式特效依赖用户在本任务中的选择）

## 目标

为待办 BL-065（视觉特效）中与战斗手感最相关的部分做可操作原型，2～3 套风格方案，由用户试玩挑选，后续批次据此正式实现。**只做原型，不改正式代码。** 全部特效用程序绘制（与 UI-001 的墨线、纸面风格同源），不依赖外部美术资源。

## 依据

- 待办 BL-065（攻击与命中、向上和向下攻击反弹、投射物反弹、闪避与无敌、可能性获得与消耗、恢复、受击与低生命、复活、敌人与 Boss 死亡等）；T6 特效条目；路线图 M3。
- 协作规范 V2.3 §3.3：明显改变观感的表现先做原型、用户挑选后再正式实现。
- 已选视觉：EXP-002 样张二（UI-001 样式模块：`DuskStyle`、`InkDraw`、霞鹜文楷）。

## 现状（起草时核对 master@ae8a9c5）

- 玩家：`player/placeholder_visual.gd` 只有受击整体变红 0.2 秒、获得可能性时一圈绿色扩散环、无敌时半透明闪烁、闪避时按可能性充足 / 不足着色，命中时播放程序生成的命中音。
- 敌人：各 `*_visual.gd` 有灰盒攻击前摇警示；死亡、受击无专门特效。
- HUD（UI-002）已有：可能性获得时光点飞入徽记、不足时容器发红、最后 1 点生命时画面边缘红色、透支时画面失真。本原型不重做这些，只在需要时与之配合示意。
- 项目中没有粒子节点或特效资源。

## 要求

1. **2～3 套风格方案**，每套覆盖同一组特效，方案之间在笔触（墨迹飞溅 / 光痕 / 极简几何等）、强度与持续时间上有可感知的差别：
   - 攻击挥砍轨迹（水平、上、下各一）与命中特效（含是否加入短暂停顿“顿帧”的对比开关）；
   - 向下攻击命中弹起、投射物被弹反；
   - 闪避（可能性充足与不足两种）与无敌期间的表现；
   - 可能性消耗（闪避、恢复扣费）、恢复过程（循环）与完成；
   - 玩家受击、敌人受击与死亡；
   - 复活。
2. **可玩原型**：放在 `game/prototypes/EXP-005/`，一个简化的玩家与 2～3 个靶子敌人（模拟数据，不接正式战斗逻辑），可用键盘与手柄触发上述动作；画面上有方案切换键与说明；可单独开关顿帧与屏幕震动，便于比较。
3. **性能与可读性**：每套方案在同屏多敌人时（例如 8 个靶子同时受击）帧率不明显下降；特效不遮挡敌人攻击前摇警示与 HUD。
4. 原型数据全部为模拟；不改正式场景、共享脚本、`project.godot`、输入映射或存档。

## 接口与影响

- 正式实现时预计挂在 SYS-010 的动画状态查询与现有信号上（`attack_started`、`hit_confirmed`、`damaged`、`gained`、`shortfall` 等）；若某特效需要现有代码没有的数据（例如弹反事件、敌人死亡位置），在交付记录列出，供正式任务另立系统部分。
- 顿帧、屏幕震动若被选中，属于手感改动，正式化时需单独评估对判定与计时的影响（暂停与时钟规则不变）。

## 完成标准

1. 原型可用键盘与手柄操作，方案切换与开关说明在画面上；冒烟测试覆盖每套方案的每个特效能被触发、按时结束、不残留，断言读实际绘制记录。
2. 1280×720 与 1920×1080 下特效不遮挡 HUD 区域与敌人前摇警示；8 个靶子同时受击时记录帧时间。
3. 交付记录附各方案截图（或分帧图）与对比表（含推荐与理由，推荐写在中立对比表之外），以及顿帧与震动的建议。
4. 现有全部测试通过（原型不进入 G2 登记，冒烟测试独立运行）。
5. G4（用户）：试玩后选定风格方案，并决定顿帧与震动是否采用。
