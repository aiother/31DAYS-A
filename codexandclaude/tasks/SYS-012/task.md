# SYS-012：关键演出流程框架

状态：已批准（2026-10-24 用户批准）｜级别：L｜实现：Codex｜审查：Claude
工作区：worktrees/codex｜基线：本任务卡合入后的 master 最新提交（实现者在交付记录中写明完整 SHA）｜依赖：无（不需要正式演出资源）；与 Claude 的 PLN-002、DOC-010、FX-002 并行

## 目标

完成待办 BL-081 的流程衔接部分：建立统一的关键演出播放入口，把现在分散在各会话中的演出状态（开场坠落、Boss 登场、7 相遇与注视、10 救场、最终胜利与 V0.1 结束）收拢到同一套流程上，统一处理操作锁定、暂停、跳过、计时、存档与失败重试。先沿用现有几何与文字占位，正式演出内容（镜头、实时演出、过场动画）以后由 Claude 接入时只需替换演出内容，不改流程。

## 依据

- 待办 BL-081；T6-D3（关键演出清单：开场坠落、两场 Boss 登场的镜头特写加实时演出、7 相遇与注视获得、10 救场、最终战胜利的实时演出加过场动画、V0.1 结束）。
- 计时：T4 与 T3 §10（剧情、普通对话、救助放弃确认、死亡动画与菜单停表；最终战预算不回补）；2026-10-18 三日自然计时修订（剧情事件取较晚日期、跨日事务失败回滚时钟）。
- 存档：各实施修订的“剧情奖励与完成标记同次写盘，失败回滚并保留重试”“未保存的演出可重播”“已保存的救场跳过、不重复补满”（T2 §10、T3 §8～§9、T5.4）。
- 已有正式界面：对话（UI-008）、敌人介绍卡与战场横幅（UI-009）、结束与超时界面（UI-005）；暂停菜单（UI-003）。

## 现状（起草时核对 master@091d701）

- 演出状态由各会话各自维护：`StartRoomSession.intro_active`（开场坠落与起身）、`BossSession.intro_active`（Boss 登场）、`FinalBattleSession` 的 `cinematic` 枚举与 `_start_pending` / `_win_pending` / `_ending_active` 等标志、`game/ui/cinematics/rescue_overlay.gd`（10 救场斩击与空场）。
- 计时、HUD 隐藏、操作锁定、暂停与音乐状态（SYS-011 的“剧情”背景槽）分别读取这些标志；没有统一的“当前是否在演出、演出能否跳过、演出结束后做什么”的查询。

## 要求

1. **演出入口**：一个服务或组件（例如 `CinematicDirector`），提供开始、推进、结束、查询当前演出的接口；每段演出由数据描述（编号、是否锁操作、是否可跳过、结束时写入的事件、结束后的衔接），演出内容（占位或正式）与流程分开。
2. **接入现有演出**：开场坠落与起身、两场 Boss 登场、7 相遇（首见剧情）与注视获得（返回 7 结算）、10 救场、最终胜利与 V0.1 结束，全部改由该入口驱动；现有表现、时长、存档字段与结果不变。
3. **统一规则**：
   - 演出期间按现行规则停表（计时器读同一个查询），HUD、操作锁定与 SYS-011 剧情背景槽读同一状态；
   - 暂停菜单可在演出中打开，暂停冻结演出；
   - 跳过：只有现行规则允许的演出可跳过（例如未保存的演出可重播，不是可跳过），默认不新增跳过；如需新增跳过，先列出并请用户决定；
   - 写盘：演出结束时的事件、奖励与完成标记同次保存，失败回滚并保留重试；死亡、读档后按已保存状态跳过或重播，与现行规则一致。
4. **不改玩法**：不改剧情内容、奖励、日期推进、波次与胜负规则；只把流程收拢。
5. **文档**：`game/docs/` 新增演出接入说明：演出清单与数据格式、流程状态图、如何接入正式镜头与过场动画、与计时 / 存档 / 音频的关系。

## 完成标准

1. 自动测试使用真实会话与真实输入：每段演出由真实流程触发，经新入口开始与结束；演出期间停表、操作锁定、HUD 与剧情背景槽状态正确；暂停冻结演出；写盘失败回滚并可重试；死亡、读档后已保存的演出不重播、未保存的可重播。
