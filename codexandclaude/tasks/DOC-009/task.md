## 改写规则（沿用 DOC-001、DOC-008）

1. **只写现行规则**：每条已确认修订并入正文对应章节，过时表述删除；正文不再出现行内修订标记、顶部补丁或按日期追加的修订段。
2. **不新增、不改变规则**：每句话都能追溯到原冻结内容或某条已确认修订；歧义按待决事项总表 B 类的现行结论与 T4、T5.4 的已确认规则解释，交付记录逐条写明依据；无法确定的保留为待决，不自行裁定。
3. **规格优先于代码**：不以“代码已经这样实现”为依据；规格与代码不一致写进交付记录。
4. **保留约束，不只保留数值**：存档兼容、旧档补发、互斥、重试、回滚、“不新增地图 / 字段 / 系统”等约束都是规则，不能和测试项数、实现过程描述一起删掉。验证证据可以改为引用 `game/docs` 实施说明。
5. **保留结构**：保留现有 §1～§13 编号与标题（其他文档有“见 T3 某节”的引用）。追加修订并入对应章节：救助与成长并入 §8、§9，闪避速度并入 §8，药包并入 §5 或 §11，日期过期并入 §9，画面表现并入相应章节。
6. **§12 与 §14**：
   - §12 只保留仍未确定的边界；已确认的条目并入正文，并在交付记录中说明去向。
   - 原 §14“来源与确认记录”与变更记录合并为新的最后一节。
7. **变更记录表**：列日期、变更内容、来源（谁确认、出处），覆盖原文全部修订；本次改写作为最后一行。
8. **只改 T3**，外加 T1 那一处引用：发现 T4～T5.4、`game/docs` 与现行规则不一致时写进交付记录，不在本任务修改。
