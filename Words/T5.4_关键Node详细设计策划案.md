## 1. 范围与Node定义

Node记录需要独立管理的关键功能逻辑，不记录Room内所有地图物件。判断依据为是否影响剧情、永久成长、地图状态或需要独立保存；普通批量敌人、重复陷阱、装饰与普通箱子通常由Room配置和生成点管理。

剧情、NPC交互、检查点、Boss/精英事件及限制门需要关键Node。首次敌人教学可作为首次遭遇Node，但不将每一只普通敌人分别建为设计Node。

Room负责空间、元素数量与分布；Node负责重要事件、交互、触发与持久状态。本版与[T5.3 Room规范](T5.3_Room设计收束规范.md)、[T5.2架构规范](T5.2_区域架构收束规范.md)衔接。

本次归档最终表27个Node，每个20项字段。范围为荒地13个、田野5个、逆时战场9个，关联11个已有Room；未为其他Room补造Node。空白显示未填写，不等同于否、无或已完成。

## 2. 编号、归属与字段职责

Node编号采用RoomID_N序号形式，例如HD_10001_1_N001。每个Node直接属于Room，通过Room关联Scene与Region；四项身份必须一致，编号唯一。序号可有间隔，不为补齐数字创建节点。

| 字段组 | 原表字段 |
| --- | --- |
| 身份与分类 | Node编号、Node名称、所属Region、所属Scene、所属Room、Node类型 |
| 功能定位 | Node作用、玩家体验目标 |
| 触发规则 | 触发方式、触发条件、是否一次性、是否可重复 |
| 内容表现 | 发生内容、玩家控制状态、对话需求、动画需求 |
| 奖励与变化 | 玩家获得、世界变化 |
| 保存与时间 | 死亡后状态、时间变化 |

类型名称以最终表为准，包括出生/剧情、教学触发、检查点、敌人演出、敌人、BOSS、Boss事件/连接、NPC、剧情、NPC事件、任务/NPC、战斗事件、剧情/战斗事件。它们是本版填写分类，不额外新增战斗或存档系统。

### 6.3 10救场条件与保存

N002原表列出三项候选触发：玩家即将遭受致命攻击、幸存者战士计数低于50%、第一波结束且第二波敌人出现。共享一个一次性救场事件，完成状态保留；条件具体优先级见第7节。

演出为赤红战士手持镰刀与锤从天而降，时间静止并打断敌人，超大范围攻击秒杀当前全部敌人，直接将玩家可能性恢复至上限。结束前玩家不可操控，包含对话、全屏斩击和破碎特效。

这一最终表将秒杀范围明确为当前全部敌人，比T2“威胁单位”记录更具体；不新增重复救场或满生命奖励。N004死亡后衔接大战，不重新播放已保存的N002剧情。

### 6.4 倒计时与增援结算

N004触发第三日15分钟倒计时；若第三日剩余时间少于15分钟，则以当前剩余时间为准。有效战斗窗口不超过15分钟，不额外延长第三日。倒计时显示：余时大于15分钟时显示加速并定格在15分钟，这只是视觉表现，计时规则不变，第三日多出的时间不被消耗；余时不足15分钟时钟表显示真实剩余预算（2026-10-20 用户确认，待决事项总表 A-016）。

N005在N004之后运行：

- 倒计时结束且战斗尚未结束：进入失败结算。
- 倒计时结束前进入最后一波：触发最终增援，大量幸存者加入并出现平台，玩家可避开下方混战。
- 倒计时结束前战斗胜利：终止倒计时，结算为胜利。

“安全感/持续可能性恢复”是增援与大战Node填写的反馈，其来源为友军击杀：友军击杀敌人时，玩家照常按敌人类型获得可能性（已由中心战场首段混战修订确认）；不另设自动回能或周期发放。此口径由用户于2026-10-19裁决（待决事项总表A-003）。

### 6.5 胜利对话与结束

最终战胜利 → N001与10对话 → 对话完成 → N006胜利演出与V0.1结束。幸存者欢呼，10在战场中央望向夕阳并回身向玩家伸手，镜头从2D转为播片。N006完全失去控制。

N001的发生内容引用N006，N006又要求N001执行完毕：这是条件衔接，不实现为相互反复调用。胜利状态与对话完成标记必须各自清楚记录。

## 7. 未填写与实现前需明确的边界

- 检查点：自动激活与用途已填，但判定范围、控制状态、触发次数和保存字段多为空；共同规则可以引用T5.2，实例缺项不伪装已填写。
- 天人首次介绍：表中Node类型为敌人，但一次性规则指介绍事件；同一Node应区分介绍完成标记与敌人重置，不能用单一旗标使敌人永不再生成。
- 救场条件：低于50%的计数基准与T2“达到一半”的边界有差异；第三项是否兜底、三项是否或关系及同帧优先级需明确。
- 重复次数：N003同时填是否一次性为是，是否可重复为每波次重复2次；需要区分首次加入事件与每波增援行为。保留原值，不自行选择其中一条。
- 大战重试：N004一次性为是、不可重复，却明确死亡后重进Room直接触发；N004/N005死亡后状态为否。需区分首次剧情完成、单次战斗实例和可重试的阶段控制。
- 倒计时：N004启动时点、死亡重试是否重置剩余计时、剧情/菜单暂停、同帧胜利与超时优先级需明确；不把“死亡不额外推进时间”解释为免费重置15分钟。
- 失败结算：最终战超时未结束为失败，显示“未来已失”界面，提供重试与返回标题，重试规则见“2026-10-17实施修订：10强化与最终战灰盒闭环”（2026-10-19 用户裁决，待决事项总表 A-011）；不新增完整多结局，不将超时设为胜利。
- 日期推进：第二日检查点与第三日通路的具体状态判定须防倒退、防重复推进；7剧情已触发与已完成的差异需明确。
- 奖励：7剧情补满可能性与注视奖励仍需明确上限变更顺序；增援“持续可能性恢复”以友军击杀时玩家照常获得可能性为来源，不另设数值，见第6.4节。
- 最终结束：最终胜利并完成与10的对话及结束演出后保存V0.1结束状态；已通关的存档不能再进入，选择该槽时提示“游戏已通关”（2026-10-19 用户裁决，待决事项总表 A-013）。

这些是配置记录内尚需明确的实现边界，不改写最终表，不代表Node已通过游戏运行验证。
