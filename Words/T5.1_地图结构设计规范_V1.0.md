# 《末日前31天》地图结构设计规范 V1.0

阶段：T5.1 地图架构规范｜版本：V1.0｜整理日期：2026-10-10

## 1. 适用范围与设计节奏

本规范作为后续地图设计的统一标准，采用连续世界、分区空间管理与节点事件组织的结构。

开发节奏：先完成设计规范冻结 → 再进入下一阶段具体设计 → 不提前扩展开发内容。

T0～T4已完成主体设计冻结，T5地图结构设计进行中：T5.1制定本规范，后续T5.2开展V0.1区域设计，T5.3开展房间与节点设计。本次不填写荒地、田野、逆时战场的具体房间，不提前进入美术或程序实现。

本规范可用于后续完整版区域设计，但通用表中的Boss、能力门、解谜等字段不自动扩大V0.1范围；当前制作内容仍遵守T0及已有冻结规则。

## 2. 地图层级定义

| 层级 | 名称 | 定义 | 主要作用 |
| --- | --- | --- | --- |
| 世界层 | World | 整个游戏世界结构 | 管理所有区域关系 |
| 区域层 | Region | 一个完整生态/剧情区域 | 玩家认知中的大区域 |
| 场景层 | Scene | 区域中的大型连续空间 | 美术、玩法、事件组织 |
| 房间层 | Room | 程序管理的空间单元 | 加载、敌人、交互管理 |
| 节点层 | Node | 房间中的具体功能点 | NPC、敌人、机关、物品 |

层级关系：World → Region → Scene → Room → Node。

玩家看到的是连续世界，程序管理的是分区空间。房间大小可以不同，数个房间可组成一片较大的连续场景，房间之间支持无缝衔接。不按“一个房间就是一个独立关卡”的方式定义地图。

## 3. Region（区域）设计规范

Region是玩家理解世界的位置，是完整生态与剧情意义上的大区域，不是单个房间。区域承担世界位置、主题、情绪、主要玩法、敌人生态、NPC与核心事件等设计。

V0.1后续依次设计荒地Region、田野Region、逆时战场Region。聊天中的“A区外围 → 荒地/田野/逆时战场”用于说明世界位置关系，不新增一个夹在World与Region之间的正式层级。

## 4. Scene（场景块）设计规范

## 5. Room（房间）设计规范

Room是可以独立管理、但玩家感觉连续存在的空间单位。房间不是关卡，只是空间管理单位，可管理加载、敌人和交互等内容。

示例：玩家感觉是一整片巨大麦田，程序可按Room01、Room02、Room03分区管理。是否独立加载记录在设计表中，本规范不提前选定具体加载技术。

## 7. 空间连接 Connection

以空间连接替代旧表的“出口方向”。连接不是出口，连接代表空间关系，不要求一个Room只有一个固定入口或出口。

一个Room可以拥有多个Connection，房间相连的位置均可形成连接，并可配置普通通行、能力门、剧情锁或时间锁。示例：Room A连接荒地入口、高台隐藏区域、地下通道、田野方向。

## 8. 能力门 Ability Gate

能力门独立管理，不作为Room自身的定义。能力门独立于地图空间划分，避免把空间设计与能力解锁混在一起；通过所在位置与连接记录关联具体空间。

示例：裂缝当前无法通过，需要破障，解锁后进入隐藏区域。此例只说明能力门字段，破障仍不纳入V0.1制作范围。

## 9. 特殊房间与进入条件

删除普通房间通用的“固定进入状态”。普通空间不应强行要求玩家每次进入时具有某个固定生命、资源或叙事状态；特殊空间才记录必要进入条件。

| 类型 | 是否允许设置特殊进入限制 |
| --- | --- |
| 普通Room | 否 |
| 探索区域 | 否 |
| 普通战斗 | 否 |
| NPC区域 | 否 |
| 剧情演出房 | 是 |
| Boss区域 | 是 |
| 结局区域 | 是 |
| 时间事件区域 | 是 |
| 能力门后区域 | 是 |

“进入条件”用于能力门、剧情锁、时间锁、Boss锁等特殊连接或空间，不恢复为所有Room必填的固定进入状态。空间连接仍可记录关闭与解锁条件，不能把普通Room不设强制进入状态解释为所有连接永远开放。

特殊类型表说明限制适用范围，不表示每个特殊空间必然有锁，也不改变T2强制战斗期间的区域封锁规则。Boss类型属于通用规范能力，不能据此自行新增V0.1 Boss。

## 10. 地图设计原则

1. 玩家看到的是连续世界，程序管理的是分区空间。
2. 房间不是关卡，房间只是空间管理单位。
3. 连接不是出口，连接代表空间关系。
4. 能力门独立于地图空间划分，不把地图设计和能力解锁混在一起。
5. 时间会改变地图状态，同一个Region在不同时间可能呈现不同世界状态。

时间变化在Region、Scene和Node等设计表中记录，具体规则遵守T4，持久事件与成长遵守T3。层级职责和空间连续性应保持一致，不能因拆分Room而把玩家体验切成互不关联的独立关卡。
