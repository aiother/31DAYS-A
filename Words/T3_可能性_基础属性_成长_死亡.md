# 《末日前31天》V0.1 策划案：T3 可能性 / 基础属性 / 成长 / 死亡

版本：V0.1｜状态：主体规则与数值已冻结，实现边界见第12节｜整理日期：2026-10-07

**关联修订标记（2026-10-15，同日追加）**：下攻击命中弹起高度改为长按跳跃最大高度的50%，覆盖此前“修订前的2倍”规则，详见T1/T2本日追加修订。下攻击伤害仍为5；本次不改变生命、可能性或奖励数值。

## 1. 系统目标与资源循环

可能性是人与世界产生连接后获得的未来可能。战斗是基础获取方式，帮助NPC提供额外资源与永久成长。可能性同时用于滑步与生命恢复，让玩家在机动与生存之间做选择。

资源闭环：战斗/帮助NPC → 获得可能性 → 闪避/恢复消耗 → 继续探索与战斗。

成长闭环：完成7事件 → 获得7的注视 → 有效帮助不同NPC → 提高可能性上限 → 增强持续探索能力。

死亡闭环：HP归零 → 倒地与死亡反馈 → 死亡菜单 → 检查点复活 → 资源损失与敌人重置 → 重新挑战。

本节冻结设计与初始平衡基准，不表示游戏实现或运行测试已完成。T0范围、T1操作和T2战斗规则继续有效；本轮确认的天人奖励数值覆盖T2旧描述。

## 2. 基础属性与透支额度

| 设计项 | 冻结值/规则 |
| --- | --- |
| 玩家基础生命上限 | 5 |
| 开场生命值 | 3，高空坠落后的低生命状态 |
| 生命最低值 | 0，HP归零进入死亡流程 |
| 玩家基础可能性上限 | 10；成长后最高15 |
| 开场可能性 | 3 |
| 可能性最低值 | 改称“可能性透支额度”；余额下界为-9 |

正常可能性区间为0至当前上限，初始为0～10；负数表示提前消耗尚未发生的未来，允许的透支区间为-9～0。成长提高正常储存上限，不改变已冻结的-9透支下界。死亡后负数清零，不执行负数乘50%的保留计算。

V0.1永久属性成长只开放可能性上限，10的生命上限成长不正式开放。不新增独立体力系统。

## 3. 可能性获取与上限

| 设计项 | 获得值/规则 |
| --- | --- |
| 击杀无色实体 | +2 |
| 击杀单色实体 | +7 |
| 击杀天人战士 | +11；以本轮确认数值为准，覆盖T2“较少可能性”的旧描述 |
| 帮助NPC | 一次有效帮助获得+4可能性；永久上限成长另按第8节结算 |
| 剧情奖励 | 原表数值填写10；7首次恢复满可能性的既有约束仍保留，结算口径见第12节 |
| 超出上限 | 超过当前可能性上限的部分浪费，不转化为货币或其他资源 |

击杀奖励直接进入玩家资源并播放获得特效，沿用T1/T2。不新增随机战利品玩法，指定固定掉落仍按T2处理。

获得可能性时按当前余额增加，并受当前上限约束；负余额可由获取资源逐步偿还。正常击杀与救助收益不会扩大-9透支额度。【2026-10-15用户追加确认】敌人重置后再次击杀仍获得可能性，允许反复往返不同场景补充战斗资源；单个死亡实例只结算一次，此规则不开放NPC一次性事件重复领奖。

## 4. 可能性消耗与连闪

| 设计项 | 冻结值/规则 |
| --- | --- |
| 恢复生命 | 一次完整恢复消耗3可能性 |
| 恢复量 | 一次完整恢复2生命，覆盖原表恢复5生命 |
| 闪避基础消耗 | 第一次连续滑步消耗1可能性 |
| 连续闪避递增 | 每次递增1；第一、第二、第三次分别消耗1、2、3可能性 |
| 连闪重置 | 1.3秒没有闪避后，恢复为第一次消耗 |
| 可能性不足 | 仍可进入资源不足的闪避状态：前摇较大、无敌帧减少 |
| 恢复不足 | 可能性不足一次完整恢复成本时，不能启动恢复 |

连续滑步最多3次，三次合计消耗6可能性。1.3秒按未发生闪避的间隔判断，具体计时起点见第12节。【2026-10-15追加修订】支持地面/空中左右闪避，共用连闪成本、计数、重置与透支规则；能穿越体型较小敌人，不作为任何必经地形的通行条件。空中闪避不重置跳跃、不悬空，其余生命/恢复/收益规则不变。

恢复不使用透支：当前可能性小于3时禁止启动。滑步可在低资源时以较大前摇和较少无敌帧维持操作能力；不能据此把余额扣到-9以下。【2026-10-15确认】扣费会低于-9时拒绝本次滑步。

## 5. 恢复系统

| 设计项 | 冻结规则 |
| --- | --- |
| 恢复判定 | 按下恢复键立刻进入状态，并在开始时扣除3可能性；持续长按2.8秒 |
| 被打断消耗 | 被攻击打断时，本次已扣除的3可能性全部损失，不恢复生命；不再重复扣除 |
| 满血限制 | 满血禁用恢复动作 |
| 恢复上限 | 不允许超过最大生命值，完成时最多恢复至5生命 |

恢复期间不能移动，战斗中允许使用；必须寻找明显安全窗口。2.8秒完成后一次性恢复2生命，不在过程中分段回血。当前生命为4时完成恢复只到5，溢出的恢复量不增加生命上限。

闪避可取消恢复动作，沿用T2；【2026-10-15用户确认】主动滑步取消、提前松键均不退还已扣3可能性，未完成则不回血。

## 6. 玩家受伤

| 设计项 | 冻结值/规则 |
| --- | --- |
| 基础伤害档位 | 采用轻、中、重攻击档位 |
| 轻攻击伤害 | 1点，占基础最大生命的20% |
| 中等攻击伤害 | 2点，占基础最大生命的40% |
| 重攻击伤害 | 3点，占基础最大生命的60% |
| 环境伤害 | 1-2点，陷阱与高空坠落等沿用受击体系 |
| 最低伤害 | 造成伤害时最低1点；无敌期间不应按最低伤害强行扣血 |

普通受击轻硬直、轻微击退，硬直期间短暂无敌。重攻击危险度较高，需要可读的前摇与可应对窗口；具体哪些攻击可打断仍遵守T2“符合条件”规则，不由数值章节改成所有重攻击均可打断。

## 7. 玩家输出与敌人生命

| 设计项 | 冻结值 |
| --- | --- |
| 基础伤害单位 | 普通攻击第一段5点 |
| 第二段倍率 | 第二段仍为5点，相对第一段为1倍；击退更强、后摇更长 |
| 上攻击伤害 | 5点，保留较高击退 |
| 下落攻击伤害 | 5点，命中后向上弹起；【2026-10-15追加关联修订】弹起高度为长按跳跃最大高度的50% |
| 投掷物反弹伤害 | 5点，符合条件的非子弹投掷物可反弹 |
| 无色实体生命定位 | 13点，理论需要3次普通攻击 |
| 单色实体生命定位 | 21点，理论需要5次普通攻击 |
| 天人战士生命定位 | 31点，理论需要7次普通攻击 |

理论击杀次数为生命值除以5后向上取整，前提是每次攻击命中并结算完整伤害，不计格挡、闪避或特殊减伤。每次攻击动作对同一目标只结算一次伤害，可同时命中多个目标，沿用T2。

三类敌人分别教授操作、判断、博弈；数值不替代AI与攻击模式差异。不新增正式削韧数值系统或Boss。

## 8. 成长系统

| 设计项 | 冻结值/规则 |
| --- | --- |
| V0.1成长核心 | 永久提高可能性上限 |
| 7首次奖励 | 完成首次救助任务、获得7的注视后，上限+2，10→12 |
| 后续成长条件 | 每一次有效帮助不同NPC，触发一次后续成长 |
| 单次成长量 | 每次上限+1 |
| V0.1成长次数上限 | 首次+2之后，再允许3次+1；包含首次奖励共4次上限成长，最终上限15 |
| 重复救助 | 同一NPC不能反复触发成长计数 |

本轮明确采用上限15：10 → 12 → 13 → 14 → 15。覆盖原表“5点”和聊天评审“最多5次”的歧义，不采用上限16或17。

帮助奖励+4可能性与永久上限成长属于不同奖励；达到成长上限后不再提高上限。重复NPC能否再次获得普通帮助资源奖励，原表没有明确，见第12节，不将“不能重复成长”扩写为所有奖励都可重复或都不可重复。

## 9. 7的注视与任务选择

| 设计项 | 冻结规则 |
| --- | --- |
| 生效时间 | 完成7剧情后立即永久生效 |
| 有效行为 | 恢复NPC生命；在NPC面前击杀当前场景全部敌方单位 |
| 失败任务 | 玩家选择不帮助并离开，任务永久失败 |
| 失败后补救 | 不能返回补救 |

离开前增加明确提示与确认，说明这是会失去救助机会的选择。聊天示例“前方的人们已经没有多少时间了”用于说明提示意图，具体台词和UI留到后续制作。

救助行为通过NPC与事件记录判定，死亡不会回滚已完成事件或重复发放成长。两种帮助行为对同一NPC不能各刷一次成长。

## 10. 死亡系统与复活保护

**实施标记（2026-10-15追加）**：灰盒已接入自动检查点、分槽存档、正常载入与死亡可能性损失，见[检查点实施记录](../game/docs/checkpoint_implementation.md)。正式地图检查点实例、NPC/日期/成长等持久化在对应系统实现后接入；原生命测试场景仍保留无存档出生点重试。

| 设计项 | 冻结值/规则 |
| --- | --- |
| 死亡判定 | HP归零后禁止移动、攻击、恢复等操作；仍可打开菜单；播放倒地与死亡动画 |
| 倒地时间 | 1秒；死亡动画结束后显示死亡菜单 |
| 复活生命 | 检查点复活后恢复满生命，即5 |
| 复活可能性 | 非负余额保留死亡时当前可能性的50%；负数清零为0 |
| 可能性损失比例 | 非负余额损失50%；不对永久上限扣减 |
| 敌人状态 | 非Boss敌人重置；V0.1不新增Boss，因此本版敌人按此规则重置 |
| NPC/剧情状态 | 已完成NPC事件不回滚 |
| 检查点状态 | 保存地图进度、剧情、成长与已获得物品 |
| 复活无敌 | 3秒，沿用T1冻结值 |
| 无敌解除 | 主动攻击不提前解除复活无敌 |

流程：HP归零 → 1秒倒地 → 死亡动画 → 死亡菜单 → 选择返回检查点 → 满生命复活 → 按规则保留可能性 → 敌人重置 → 3秒无敌 → 重新挑战。

“死亡菜单”覆盖原表“结束菜单”名称，与V0.1胜利后的通关结束菜单区分。死亡菜单包括返回检查点、返回标题、设置；倒地1秒不等于死亡动画与菜单等待总时长。

【2026-10-15用户确认并实施】奇数可能性的50%保留向下取整，例如3→1、5→2；负数清零。资源不按检查点历史余额全量恢复；地图、剧情、成长与物品的持久保存避免死亡后重复刷奖励。

## 11. 资源防卡死

| 设计项 | 冻结规则 |
| --- | --- |
| 零可能性状态 | 攻击、移动、资源不足状态下的闪避、救助NPC仍可用；移动与攻击不能被资源锁死 |
| 无法恢复状态 | 低生命且无法恢复时，通过救助NPC或击杀敌人重新获得可能性 |
| 最低生存保障 | -9透支额度提供缓冲，死亡时负数重置为0；强制战斗低资源情形提供残存可能性实体 |

保底表现命名为“残存可能性实体”：在原表描述的强制战斗资源困境中，生成1-2个无伤害空中无色实体，供玩家击杀恢复可能性。不将此机制扩大为随处刷新或无限刷资源的系统。

原表同时提及Boss战；该条件仅为未来适用描述，V0.1仍不新增Boss。低资源触发阈值、一次生成1个还是2个、重触发时机、实体存活上限与是否采用普通无色实体+2奖励等边界尚需明确，见第12节。

## 12. 实现前需明确的边界

以下事项没有在已读取的填写和确认中形成唯一结论，保留为实现细则；不从示例推定新冻结值：

- 剧情奖励：原表写10，同时既有约束写7首次“恢复满可能性”。成长后上限为12或更高，需明确固定+10还是补至当前上限，以及与首次+2奖励的结算顺序；不得把两种奖励同时叠加。
- 透支边界【2026-10-15已确认并实施】：滑步成本跨越-9则拒绝扣费与发动；到达-9后不能继续滑步。余额小于当次完整成本视为资源不足。前摇、无敌帧具体值仅作Resource灰盒调校，未冻结，见实施记录。
- 连闪计时【2026-10-15已确认并实施】：从上一次实际滑步发动起计算1.3秒，无效按键不重置计时。
- 主动中止恢复【2026-10-15已确认并实施】：提前松键与滑步取消不退款，已扣成本全部损失且不回血，与受击打断一致。
- 死亡保留【2026-10-15已确认并实施】：非负可能性50%保留向下取整；负数清零。正常退出重进保留资源，不执行死亡扣减，也不发放复活无敌，沿用T7已填写规则。
- 重复帮助：同一NPC不得重复成长，普通+4资源奖励是否只发一次，以及两种帮助行为的完成记录粒度仍需明确。
- 保底实体：精确触发条件、数量选择、奖励、生成位置、重触发与存活限制，需避免形成无限刷资源或仍然无法恢复的状态。

这些细则必须在对应功能实现验收前明确并验证，不将存在未决边界等同于已经证明无软锁。

## 13. 设计验收与验证重点

- 资源闭环：战斗获取的可能性支持滑步与恢复，消耗后仍有重新获取资源的途径。
- 成长闭环：帮助NPC → 7的注视 → 可能性上限成长成立；10→12→13→14→15，不重复计数。
- 死亡闭环：死亡 → 50%非负资源损失或负数清零 → 检查点满生命复活 → 敌人重置 → 再次挑战；剧情、成长、物品不回滚。
- 无软锁：低生命、零或负可能性下，核心操作和必要通行可用；强制战斗保底实际可击杀并提供恢复路径。

灰盒验收应覆盖满血与不足资源禁用恢复、2.8秒一次性回血、开始扣费及攻击打断、1/2/3连闪成本与重置、透支下界、收益溢出、奇数与负数死亡结算、NPC重复事件、永久失败确认、复活攻击不解除无敌及保底实体行为。

当前文档验证只检查策划内容、数值关系和规则一致性；游戏运行验收须在实现后完成。
