## 2. Connection空间连接规则

| 设计项 | 最终规则 |
| --- | --- |
| 连接是什么 | 描述世界空间关联，包括共同场景房间的无缝连续、不同场景连贯转场、区域协调分割及剧情表现；不是传统出口 |
| 哪些层级存在连接 | World、Region、Scene、Room、Node任何层级均可存在Connection |
| 玩家看到的连接形式 | 道路、隧道、门、大型雕像、机关、过场动画、交通工具等 |
| 默认开放连接规则 | 普通连接无条件、无阻挡 |
| 需要能力才能通过的连接 | 使用特定能力攻击或解除；能力门独立管理 |
| 需要剧情事件开启 | 完成前置剧情 |
| 因时间变化开放/关闭 | 等待特定天数，按Time State配置改变通行 |
| 是否存在击败敌人后开放 | 战斗锁：结束指定战斗且存活后开放 |
| 是否存在击败Boss后开放 | Boss锁：击败指定Boss后开放；为通用类型，不据此扩大V0.1 Boss范围 |
| 开放状态有哪些 | 开放/关闭/变化，定义见下表 |
| 已开启连接是否永久存在 | 原表确认是；已开启连接持久存在与动态通行的边界见第7节 |
| 玩家如何知道连接状态 | 剧情与环境提示 |

| 状态 | 含义 |
| --- | --- |
| 开放 | 玩家可直接通过 |
| 关闭 | 当前无法通过 |
| 变化 | 根据时间、剧情、能力动态改变 |

隐藏属于未发现的Connection，不作为连接状态。Connection表现不决定Connection类型，一扇门可对应普通、能力、剧情或时间连接，类型由规则决定。

后续连接记录应关联目标、类型、状态、条件与回访属性。普通Room不限制固定进入状态，不意味着所有特殊连接都必须开放。

## 3. Time State时间状态规则

| 设计项 | 最终规则 |
| --- | --- |
| Time State是什么 | 地图在不同天数下的状态层，独立于空间层级 |
| 一个区域有多少时间状态 | 通用结构为指定时间前、指定时间时、指定时间后，不固定完整日期数量 |
| 哪些内容会变化 | NPC、敌人、环境、资源 |
| 场景如何变化 | 美术与演出方式改变 |
| NPC是否死亡、移动、改变状态 | 支持存活、死亡、转移、敌对化及其他状态变化 |
| 数量、类型、强度变化 | 敌人数量、类型、强度、AI模式均可变化 |
| 是否出现/消失 | 收集物可出现或消失 |
| 是否改变路线 | 解谜与路线可随时间改变 |
| 是否影响事件触发 | 时间状态影响剧情事件触发 |
| 是否永久保存 | 玩家已完成事件永久保存，不能靠时间变化重复领取奖励 |
| 玩家返回旧区域看到什么 | 返回时看到当前时间对应的场景、敌人与NPC状态 |
| 需要实现几个状态 | V0.1按天划分四个状态：第1日、第2日、第3日（至最终胜利前）、最终胜利后 |

四个状态不要求制作多张完整地图，也不提前实现31天完整内容。具体时间条件与T4事件推进相接，边界取值见第7节。原表按Day1/Day2/Day3描述的区域变化保留为配置意图，在这四个状态内映射，不凭空复制所有场景。按天划分由用户于2026-10-19裁决（待决事项总表A-009）。

## 4. Checkpoint检查点规则

| 设计项 | 最终规则 |
| --- | --- |
| 检查点是什么 | 记录玩家复活位置以及部分世界状态，不保存全部玩家状态快照 |
| 什么位置适合设置检查点 | 根据玩家心理节点设置，不按Room数量逐个放置 |
| 一个Scene多少个 | 根据Room数量设定上限，再按设计心理预期设置；未冻结具体上限公式 |
| 自动激活/互动激活 | 自动激活 |
| 玩家出现位置 | 最后激活的检查点 |
| 生命恢复 | 复活恢复满生命，V0.1为5，沿用T3 |
| 死亡后规则 | 可能性按T3结算，非负保留50%，负数清零；不是恢复检查点存储余额 |
| 复活后如何处理 | 敌人重置；【2026-10-15修订】再次击杀仍获得可能性，允许通过往返场景补充战斗资源，沿用T3及修订后T4 |
| 已完成事件是否保存 | 保留已完成NPC状态，防止重复奖励 |
| 是否保存 | 剧情状态保存 |
| 开启门、能力门是否保存 | 地图状态保存 |
| 死亡是否影响时间 | V0.1死亡不额外推进时间，覆盖原表“是” |

### 检查点保存与排除项

| 内容 | 保存规则 |
| --- | --- |
| 位置 | 保存 |
| 已激活检查点 | 保存 |
| 剧情状态 | 保存 |
| 地图状态 | 保存 |
| NPC状态 | 保存 |
| 能力解锁 | 保存 |
| 当前生命 | 不保存为复活回档值 |
| 当前可能性 | 不保存为复活回档值 |
| 临时状态 | 不保存 |

永久成长与已获得物品仍按T3保留，不能因复活回滚。复活3秒无敌且攻击不提前解除，继续按T3执行。

原表生命恢复行的设计项写为“已冻结”，对应满生命复活规则，未重新开放该数值选择。

“死亡不额外推进时间”指死亡本身不加天或追加固定时间惩罚，不将其扩写为普通战斗、全部倒地动画或复活演出必然暂停基础时钟；自然计时与暂停边界按T4后续实现细则明确。

## 5. Node Scope节点作用域

| 设计项 | 最终规则 |
| --- | --- |
| Node是什么 | 可设置的最小交互/功能节点 |
| Node属于哪个层级 | Node直接属于Room，不跨级；由Room关联Scene、Region |
| 是否需要编号 | 需要唯一编号，便于程序管理 |
| 类型分类 | NPC、敌人、机关、剧情、可破坏环境、物品、检查点、能力门、触发区域 |
| 如何触发 | 自动、互动、攻击、条件 |
| 需要什么条件 | 天数、剧情状态、生命值状态、行为状态等 |
| 产生什么变化 | 移动、消失、死亡、切换、破坏、掉落、剧情开启、触发下一Node等 |
| 是否只能触发一次 | 可一次性或多次，依具体节点配置 |
| 哪些可以重复 | 机关等可重复事件；不能据此重复一次性奖励 |
| 是否受Time State影响 | 是，具体变化按节点配置 |
| 是否绑定NPC/敌人 | 可绑定角色，但不必须 |
| 死亡后是否保存状态 | Node默认不保存，由类型决定是否保存 |

| 节点状态示例 | 保存 |
| --- | --- |
| 普通敌人状态 | 否，按重置规则处理 |
| NPC剧情状态 | 是 |
| 机关开启状态 | 是 |

Node属于Room与能力门独立管理并不冲突：能力门Node记录空间触发点，Ability Gate记录解锁规则，后续通过引用关联；不改变地图层级。

原表Node_10001～Node_10009是类型配置基础，还需在T5.3为具体节点补齐所属Room、时间条件与持久状态。不能将类型模板直接当作所有实例都已完成归属与保存设计。

## 7. 配置与实现边界

- 持久连接与变化状态：已开启连接永久存在，但时间连接仍支持开放/关闭。需区分存在记录、解锁记录和当前可通行状态，不能直接取消其中一条规则。
- 时间节点：状态按天划分，日期推进到第2日、第3日时切换到对应状态（自然跨日或关键事件推进均适用，按T4取较晚日期、不倒退）；最终胜利保存后进入“最终胜利后”状态。10临界倒计时在第3日状态内运行，不单独构成状态。
- 检查点与持久化：哪些状态即时持久、哪些检查点记录，未冻结具体写盘时机；不据“不保存当前可能性”取消死亡时T3的50%结算。
- 死亡与刷新：【2026-10-15修订】敌人重置后照常发放可能性，允许往返场景补充资源；单个死亡实例只发一次奖励。Node默认不保存与一次性NPC事件奖励仍按各自规则处理，残存可能性实体保障留待对应阶段。
- 范围与编号：Boss锁、能力门是通用架构能力，不自动新增Boss或后期能力；T5原表Room编号与所属Scene冲突需后续统一，保留原引用记录。

这些边界在对应功能实现前需明确；文档规则验证不等于已经通过游戏运行测试。
