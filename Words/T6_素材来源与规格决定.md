## 2. 总原则

### 2.1 授权与来源登记

- V0.1 现阶段自用 / 小范围试玩，不公开发布、不商用。将来若公开或商用，需要重新核对每个素材的授权，所以**从现在起每个外来或生成的素材都要登记**。
- 选用免费素材时优先 CC0 或“免版税、可商用、无需署名”的授权；不用 NC（禁止商用）与 ND（禁止改编）素材；CC-BY 素材可以用，但必须登记署名信息。
- AI 生成素材：登记生成工具、套餐类型（免费 / 付费）、生成日期、提示词文件。免费套餐常常不含商用权，自用阶段可以接受，将来公开前须逐项复核。
- 登记表建议放在 `game/assets/CREDITS.md`（或同目录的表格），每行：文件路径、来源（网址或工具名）、授权、作者 / 署名要求、日期、是否改动。由 Claude 在接入时填写，用户验收时一并确认。

### 2.2 生成与交付工作流

1. Claude 按本记录的规格写提示词与验收要点（每张图 / 每段音频一条），放在对应任务目录。
2. 用户在自己的账号里生成（美术：GPT Image 2；音频：用户已有的 AI 音频工具或免费额度），挑出满意的版本，放进素材收件箱。
3. Claude 从收件箱取件：拆层、去背、缩放、命名、绑骨、做动画或剪辑，接入游戏，登记来源。
4. 用户在游戏内实机验收（G4）。不满意时 Claude 修改提示词，回到第 2 步。

素材收件箱建议放在仓库根目录 `assets_src/inbox/<art|audio>/<对象或区域>/`，放在 `game/` 之外，避免 Godot 导入原始大图。原始生成文件是否提交进 Git（体积较大）由规划会话在“风格说明与素材规格”任务里定；建议原图不提交，只提交处理后的游戏用素材与提示词文本。

### 2.3 GPT Image 2 使用要点

- 先出一张**全身设定图**（正侧面、站姿、透明或纯色背景）定形象，用户确认后再以它为参考图做部件拆分与关键帧，保证同一角色前后一致。
- 部件图要求透明背景、正侧面、关节处多留约 15% 重叠区（便于骨骼弯曲不露缝）。
- 同一角色的所有图都附上同一组风格关键词和色板（第 3 节），并以已确认的设定图作参考。
- 难以由 AI 一次拆好的部件，由 Claude 从整图手工切分后再请用户用 GPT Image 2 补画缺失部分（例如被遮挡的远侧手臂）。

## 3. 画风方向

**2026-10-30 起世界风格改为“叠放的褪色老照片”**（`Words/暗室设定.md`，用户裁决待决事项 A-021；落实见 `game/docs/art_style.md` 第 1、7 节），以下线条、上色、光与色板只适用于角色与暂留的 UI。原方向统一为“墨迹、纸色、黄昏暖光”，与已完成的 UI 样张二（`game/ui/style/dusk_style.gd`）和 FX-001 风格 D（墨迹飞溅 + 暖光 + 珍珠白）一致。具体风格说明由 Claude 在“风格说明与素材规格”任务中起草，用户定稿。要点：

- **线条**：深墨色轮廓，略带手绘抖动与粗细变化，不用干净的矢量线。
- **上色**：平涂为主，少量水墨晕染与纸张纹理；不做厚涂、不做写实光影。
- **光**：黄昏暖光从一侧打来，角色亮面带暖色边光；暗部偏冷紫。
- **色板**（取自 UI 样式模块，正式素材以此为基准）：

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 墨 INK | `#2b2420` | 轮廓、暗部 |
| 珍珠白 PEARL | `#fbf6ec` | 高光、飞溅浅色 |
| 白日纸色 | `#efe4cc` | 田野、日间底色 |
| 黄昏纸色 | `#f0cfb6` | 荒地、黄昏底色 |
| 黄昏顶 | `#7d4a8c` | 天空上部、冷暗部 |
| 黄昏底 | `#f0a050` | 天空下部、暖光 |
| 日光 | `#f4b860` | 边光、暖高光 |
| 生命红 | `#b8382c` | 生命相关，角色上慎用 |
| 可能性青 | `#2f8f88` / 光晕 `#9fe6d6` | 可能性专用，角色与场景避免大面积使用，保证可识别 |
| 成长金 | `#d9a03a` | 成长、奖励 |

- **三个区域主色调**（建议，由风格说明定稿）：荒地 = 黄昏纸色 + 灰褐瓦砾 + 紫色远景；田野 = 白日纸色 + 麦金；逆时战场 = 低饱和暗红褐 + 烟尘灰，远景有战火暖光。
- **敌人**：无色实体以墨块、剪影为主（几乎无色），单色实体只用一种强调色，天人战士在墨色中加金色或珍珠白装饰，三类一眼可分。
- 角色与背景要拉开明度：角色轮廓深、背景远景浅而淡，保证战斗可读性；FX-001 的特效不需要重做。

## 4. 美术规格

### 4.1 尺寸与比例

- 游戏基准分辨率 1920×1080（`game/project.godot`），地形瓦片 64×64 px（`game/data/world/graybox_tileset.tres`）。
- 玩家碰撞胶囊高 96 px。建议玩家**显示高度约 112 px**（头顶到脚底，在 1080p 下）。
- 角色比例按 T6-E：普通敌人 = 普通 NPC = 80% 玩家（约 90 px）；关键 NPC（7、10）= 精英敌人 = 200% 玩家（约 224 px）；Boss = 250% 玩家（约 280 px）。碰撞与美术尺寸的对应由 BL-063 落地，本记录不改碰撞。
- **交付分辨率为显示尺寸的 2 倍**（玩家约 224 px 高），在 Godot 中以 0.5 缩放显示，留出镜头特写与高分屏余量。AI 原图可以更大，由 Claude 缩到 2 倍尺寸。
- 格式：PNG，RGBA 透明背景，sRGB。纹理过滤用线性（非像素风）。

### 4.2 目录与命名

对象编号（文件名与目录统一使用）：`player`、`weapon_starter`、`seven`、`ten`、`survivor`、`survivor_warrior`、`colorless`、`monochrome`、`tian`、`boss_overlook`（渴望俯视）、`boss_parasite`（寄生同伴者）。区域编号沿用 Region id：`hd`（荒地）、`ty`（田野）、`nszc`（逆时战场）。

| 内容 | 建议路径 | 文件名 |
| --- | --- | --- |
| 角色部件 | `game/assets/characters/<对象>/parts/` | `<对象>_part_<骨骼名>.png`，例如 `player_part_arm_upper_near.png` |
| 逐帧序列（全逐帧对象） | `game/assets/characters/<对象>/frames/` | `<对象>_frames_<状态>_<两位序号>.png`，状态用映射键并把点换成下划线，例如 `player_frames_run_01.png`；同一动作每帧画布同尺寸、以脚底中点为锚点 |
| 关键逐帧 | `game/assets/characters/<对象>/keys/` | `<对象>_key_<状态>_<两位序号>.png`，例如 `player_key_attack_horizontal_active_01.png` |
| 动画资源 | `game/assets/characters/<对象>/anims/` | 沿用 SYS-010：`对象_状态_变体_连段_阶段.tres`，映射键为小写点分，例如 `player_attack_up_2_active.tres` → `attack.up.2.active` |
| 变体 | 同对象目录 | `<对象>_<变体>_…`，例如 `colorless_ranged_part_head.png` |
| 背景 | `game/assets/environments/<区域>/bg/` | `<区域>_bg_<far|mid|near>_<两位序号>.png` |
| 瓦片与装饰 | `game/assets/environments/<区域>/tiles/`、`deco/` | `<区域>_tiles_<室外|室内>.png`、`<区域>_deco_<名称>.png` |

目录为建议，规划会话可在规格任务中调整，但同一项目内只用一套。

### 4.3 骨骼与部件

按 SYS-010 约定：正式资源放在 `VisualRoot/Facing/Art` 下，Facing 负责左右镜像，动画轨道只写 Art 内的节点。所以骨骼与部件**不分左右，而分近侧 near / 远侧 far**（面向镜头一侧为 near），镜像时自动成立。

人形角色（玩家、7、10、幸存者、幸存者战士、天人）的标准 Bone2D 命名：

```
root
└ hip
  ├ spine ─ chest ─┬ neck ─ head
  │                ├ arm_upper_near ─ arm_lower_near ─ hand_near ─ weapon
  │                └ arm_upper_far  ─ arm_lower_far  ─ hand_far
  ├ leg_upper_near ─ leg_lower_near ─ foot_near
  └ leg_upper_far  ─ leg_lower_far  ─ foot_far
```

- 可选附加骨骼：`hair_1…n`、`cloth_1…n`（衣摆、披风），由风格说明决定是否需要。
- 每根骨骼对应一张部件图（`hip` 对应腰胯，`chest` 对应躯干上部）；武器 `weapon_starter` 单独成图，挂在 `weapon` 骨骼上。
- 非人形敌人（无色、单色、两场 Boss）不强制用上述骨骼，由 Claude 在拆层时按造型定，命名仍用小写英文加 `_near` / `_far`。
- 关键逐帧只覆盖对应肢体或阶段（例如攻击生效帧的整条手臂 + 武器拖影），骨骼继续负责其余部分，切换时显式设置可见性，避免双重轮廓（SYS-010 约定）。

### 4.4 动画清单

数量与复用规则沿用 T6-B1、T6-B2，映射键沿用 SYS-010 状态表。

**动画路线**（用户 2026-10-30：“二者混合，我希望有很好的动画效果全部走逐帧，但是成本太高，所以只有玩家和部分关键敌人的动画会考虑全部逐帧，大批量的敌人杂兵将会用骨骼动画处理”）：**玩家与关键敌人全部逐帧**，关键敌人为两场 Boss（渴望俯视、寄生同伴者，用户批准第十二批时确认）；**其余敌人与 NPC**（无色、单色、天人战士、幸存者战士、7、10、幸存者）用骨骼 + 少量关键帧。全逐帧对象不绑骨骼，部件拆分只作形体、分层与染色遮罩的参考。

**玩家**（T6-B1）：

| 动作组 | 映射键 | 做法 |
| --- | --- | --- |
| 待机 | `idle` | 逐帧循环 |
| 行走、跑步 | `walk`、`run` | 逐帧循环 |
| 转向 | `turn.walk`、`turn.run` | 逐帧，镜像复用 |
| 跳跃 | `takeoff`、`rise`、`apex`、`fall` | 逐帧，一套动作分四段 |
| 落地、重落地 | `land`、`hard_land` | 逐帧；重落地帧数更多 |
| 普通攻击 1、2 段 | `attack.horizontal.1/2.*` | 逐帧，一套动画 |
| 向上攻击 | `attack.up.*` | 逐帧 |
| 向下攻击 | `attack.down.*` | 逐帧；命中反弹复用跳跃 |
| 空中攻击 | 见第 6 节缺口 1 | 镜像复用 |
| 闪避（充足 / 不足） | `dodge.*`、`poor_dodge.*` | 逐帧，同一套动作微调区分 |
| 受击 | `hurt` | 逐帧 |
| 死亡 | `downed`、`fade`、`dead` | 逐帧 |
| 恢复 | `heal` | 逐帧循环（2.8 秒由循环达成） |
| 复活 | `respawn` | 逐帧 |
| 互动 / 拾取 | 见第 6 节缺口 2 | 互动与拾取共用 |

**NPC 与敌人**（T6-B2，括号内为独立动画数）：7（3）待机、劳作、对话 / 教学；10（6）待机、移动、攻击、救场、对话（移动与攻击参照玩家复用）；幸存者（3）待机、受伤、获救 / 互动；幸存者战士（4）移动、攻击、受击、死亡；无色（5）移动、近战、远程、受击、死亡；单色（6）移动、冲刺、闪避、攻击、受击、死亡；天人（7）移动、连击、重击、远程、格挡、受击、死亡；渴望俯视（5）登场、移动、攻击、受击、死亡（移动、普通近战可与寄生同伴者复用）；寄生同伴者（6）登场、移动、投射、吸血、受击、死亡。以上都允许镜像复用。

做法：渴望俯视、寄生同伴者全逐帧；其余骨骼 + 少量关键帧（关键爆发帧覆盖对应肢体或阶段，见第 4.3 节）。

### 4.5 场景

- 每个区域一套主题素材集；同一 Scene 的 Room 共用瓦片与装饰；室内、室外瓦片分开，装饰可通用（T6-E）。
- **背景**（AI 生成）：每区域远景、中景、近景各至少 1 张，横向可无缝平铺或足够宽（建议宽 3840 px 以上、高 1080～1620 px），PNG；近景层带透明。用于视差分层。
- **瓦片**（Claude 代码绘制）：64×64 网格，包含地面、平台、墙体、斜坡、高低差的边角件，墨线描边 + 纸色填充 + 区域主色。
- **装饰、障碍、检查点外观、Connection（普通通路、Boss 锁、事件路障）**：Claude 代码绘制或从 AI 背景中切出；检查点 8 个可共用一套外观按区域换色（T6-C 为 B 级）。
- **Boss 场景与时间变化**（A 级）：在区域素材集基础上加专用背景或色调变化，具体随 Boss 演出与 M5 再定。

| 区域环境音（A） | OGG Vorbis，44.1 kHz | 立体声 | 60～120 秒无缝循环 | `amb_<区域>.ogg`：`amb_hd.ogg`、`amb_ty.ogg`、`amb_nszc.ogg` |
| 音乐（B；剧情为 C） | OGG Vorbis，44.1 kHz | 立体声 | 90～180 秒，带循环点 | `bgm_<状态>.ogg`：`bgm_exploration.ogg`、`bgm_combat.ogg`、`bgm_large_battle.ogg`、可选 `bgm_story.ogg` |

- 响度建议：峰值不超过 −1 dBFS；音乐约 −16～−18 LUFS，环境音比音乐低约 6 dB；音效按听感与 C 级占位音对齐后统一微调。最终在游戏内用设置里的效果音 / 背景音滑块验收。
- 路径建议 `game/assets/audio/<sfx|amb|bgm>/`，接入方式为放入 `game/systems/audio/default_audio_map.tres` 对应槽位，不改玩法代码。
- 事件清单以 `game/docs/audio_events.md` 的事件表为准（含前摇提示音的单色 / 天人普通与重击独立槽、UI 焦点 / 确认 / 返回）。同类行为可多个键指向同一文件；若素材已按目标音高制作，把对应 `pitches` 设为 1。
- 风格方向：可能性音效是核心标志，建议“清亮的玻璃 / 风铃质感 + 轻微倒放尾音”，与可能性青色呼应；荒地 = 风声、碎石、远处低鸣；田野 = 麦浪、虫鸣、远处风铃，相对平静；逆时战场 = 远处炮火、人声嘈杂、金属撞击。音乐方向关键词：废土、黄昏、东方墨色、少量民族乐器。具体提示词由音频任务起草。

## 6. 台词

- 流程：用户先给出每个人物的口吻要点（身份、说话习惯、口头禅或禁忌、与玩家的关系），Claude 据此并对照 T3 §9、T7-C 与现有台词结构起草，用户改定后接入。
- 范围：7、10、各救助 NPC、放弃确认（例如“这里还需要你，离开后无法弥补”）、已过期 NPC 处的错失机会文本，以及演出中的台词。现有临时台词所在文件：`game/data/dialogue/outskirts_survivor.tres`、`ten_rescue.tres`、`ten_victory.tres`，`game/data/world/ravine_survivor_dialogue.tres`、`seven_dialogue.tres`、`survivor_dialogue.tres`。
- 格式：保持现有资源结构与条数、触发条件不变；每句长度以对话界面（UI-008）单行 / 双行能容纳为准，起草时由 Claude 标出字数。

## 7. 优先顺序

1. **风格说明与素材规格**：Claude 起草风格说明（关键词、色板、线条与光的规则、三区域主色调）与本记录第 4、5 节的正式规格，附 3 组提示词：玩家全身设定图、荒地背景一角、一只无色实体；用户生成后据此定稿风格。
2. **用临时玩家骨骼跑通“素材 → 动画层”流程**（可与第 1 项并行）：Claude 用代码绘制的临时部件按第 4.3 节骨骼搭好玩家 Art 子树，做 `idle`、`run`、一段攻击（含一张关键帧），经 SYS-010 映射接入，验证镜像、关键帧切换与命名规则。正式部件到位后只换贴图。
3. **玩家形象与初始武器**：设定图 → 部件拆分 → 绑骨 → 全部动画 → 用户 G4。
4. **普通音效（C 级）**：成本最低，可随时穿插；台词口吻要点也可在此期间由用户提供，Claude 起草台词。
5. **7、10**，随后 **三类敌人与幸存者**、**两场 Boss**。
6. **三个区域场景**：建议按游戏顺序从荒地开始；可能性音效与环境音随场景一起做。
7. **音乐**与**关键演出表现**（BL-081 表现部分）最后，依赖角色与场景素材。

## 8. 交给规划会话的注意点

1. **空中攻击没有独立映射键**：SYS-010 的攻击查询只有 `attack.horizontal/up/down`，空中普通攻击通过附带字段 `airborne` 区分，没有单独的键。若要给空中攻击单独一套动画（T6-B1 列为 1 个独立动画），需要在动画接入任务中评估是否让映射使用 `airborne`，或接受与地面横劈共用。
2. **互动 / 拾取没有动画状态**：SYS-010 明确“查询不新增原状态机不存在的交互或拾取动作”，而 T6-B1 要求 1 个互动动画（拾取复用）。需要立项时决定是否增加只读的互动状态投影。
3. **关键 NPC 200% 比例**：T6-E 规定 7、10 为玩家的 200%，与精英敌人同级；10 参与战斗，其现有碰撞与该比例的对应需要在 BL-063 任务中核对。本记录只按 T6-E 记录。
4. **AI 素材的一致性风险**：同一角色多张生成图之间可能走样。规格任务中应规定“先定设定图、后续一律以它作参考”，并在验收要点里列出轮廓、配色、比例三项一致性检查。
5. **原始素材是否入库**与**来源登记表位置**需在规格任务中定下。
6. 音频生成工具未指定具体产品：按“只用已有订阅 + 免费”的预算，由用户在提示词到手后自选工具，Claude 登记。
