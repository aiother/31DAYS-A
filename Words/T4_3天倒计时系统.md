# 《末日前31天》V0.1 策划案：T4 3天倒计时系统

版本：V0.1｜状态：主体规则已冻结，未决边界见第9节｜整理日期：2026-10-08｜现行版更新：2026-10-25

本文是现行规格：正文只写当前有效的日期、计时、超时与最终战时限规则，历次修订已并入对应章节，来源见第10节变更记录。本文是计时与日期推进的权威位置；资源、死亡与救助奖励见T3，战斗、10与最终战波次见T2，Node配置见T5.4。实施说明（`game/docs`）记录参数与验证方法，不改变本文规则。

全文用语：**日内时间**指当日剩余的自然时间（每日30分钟）；**第3日剩余**指第3日的日内时间；**最终战预算**指最终战正式开战（NSZC_10003_1_N004）时确定的倒计时；**正式开战**专指最终战开始计算最终战预算的时刻，不是进入逆时战场或触发10剧情的时刻。

## 1. 时间系统目标

时间不是单纯的UI数字，而是玩家压力、世界变化与剧情推进的共同变量。V0.1只验证3天框架，保留未来扩展到31天阶段系统的结构，不制作完整31天内容。

时间存在意义：暗室侵蚀随时间增强，敌人更加危险、环境更加恶劣，可帮助NPC减少，敌人数量与构成变化，剧情机会随之改变。

暗室侵蚀导致敌人更危险：主要反馈来自敌人攻击欲望、攻击方式和世界变化，不以同一攻击暗中加伤作为核心时间规则。攻击频率、范围、追击距离等是表现方向，具体参数未冻结；不据此修改T3伤害数值。

## 2. 时间核心与暂停

| 设计项 | 冻结规则 |
| --- | --- |
| 玩家是否知道剩余时间 | UI显示当前时间，地图背景随时间变化；每经过一天出现当前天数提示（HUD形式见下文） |
| 时间单位 | 游戏内时间+事件推进，按游戏物理时间推进，不计算玩家离线的现实时间 |
| 一天长度 | V0.1一天为半小时（日内时间30分钟）；完整版一天约1小时，作为未来扩展基准，不用于当前版 |
| 时间推进方式 | 基础时间自动流逝，同时关键事件强制推进日期（见下文“日期推进”） |
| 时间暂停 | 剧情进行时暂停时间，打开菜单时暂停时间；普通对话、救助放弃确认、死亡动画与死亡菜单期间也停表。普通战斗与不锁操作的敌人首见介绍卡照常计时 |
| 时间显示方式 | 数字+环境变化，见下文“HUD时间显示” |

10救场期间时间暂停沿用T2第10节。

三天并非固定一张地图对应一天：Day1覆盖坠落、荒地生存和田野认识7；Day2探索并寻找10线索；Day3进入逆时战场最终高潮。区域与日期的关系由关键事件及自然流逝共同决定。

**日期推进**：

- 自然流逝：第1日日内时间归零进入第2日，第2日归零进入第3日。
- 关键事件：7首见剧情（TY_10001_1_N002）完成后，进入沟壑入口检查点（HD_20001_1_N001）时日期至少为第2日；击败寄生同伴者、开放逆时战场通路（HD_20003_1_N002）时日期至少为第3日。
- 事件取较晚日期：日期只取“当前日期”与“事件要求日期”中较晚的一个，只在真正跨日时初始化新一天的日内时间；自然日期已到达后，事件、回访与重复检查点都不重复补时，也不倒退。
- 存档事务：事件推进日期与对应检查点或胜利通路同次保存，保存失败整体回滚（含时钟）。
- 新游戏与旧存档：新游戏从第1日开始；缺少日期的旧存档按第1日；旧第1、2日存档从采用自然计时的版本起获得当前日30分钟，不倒推历史游玩时间；旧存档缺少第3日剩余时，从采用最终战计时的版本起按30分钟初始化；已有的第3日与最终战计时原样保留。存档增加可选字段 `day_remaining`，`day3_remaining` 与最终战预算字段继续兼容。
- 保存时机：每0.5秒，以及跨日、检查点、资源变化、死亡、正常选槽与退出时保存时钟。

**HUD时间显示**（UI-002，EXP-001方案四）：

- 日常游玩时画面底部为一条地平线，太阳随当日进度从左向右移动，太阳上方纸签显示游戏内时刻（每日30分钟映射为06:00～24:00）；右下角小字“第N日 · 末日前N天”。
- 换日时中上部出现“第N日 / 末日前N天”纸签；换日前3分钟右下角提示“即将进入第N+1日”与剩余分秒；第3日没有该提示。
- 完整时间与三天进度在暂停菜单右侧时钟中显示，不新增查看时间的按键。
- 最终战倒计时位于中上部（A-016）：正式开战时第3日剩余超过15分钟，倒计时从第3日剩余加速走到15:00，这只是画面表现，最终战预算从正式开战起照常流逝；第3日剩余不足15分钟则直接显示真实剩余，并用朱红警示。读档进入已开战的最终战不重播加速。
- 画面氛围随天数进入黄昏：第1日接近日光，越往后越深，最终战为完整黄昏且光晕减弱约30%（EXP-002样张二）；生命、可能性、透支、成长、不足闪烁等关键色每一天都不变。
- 以上只改变显示方式，不改变计时规则、预算或存档字段。实现见[正式HUD实施说明](../game/docs/formal_hud_implementation.md)。

## 3. V0.1三天结构

### 3.1 Day 1：生存

- Day 1主题：生存。坠落 → 荒地 → 认识7 → 学习可能性，玩家主要目标是活下来。
- 时间结束条件：结束与7的相遇剧情，并离开7所处区域（进入沟壑入口检查点），推进到第二天；不能将仅开始对话当作已完成推进条件。第1日日内时间归零也会进入第2日。
- 世界变化：普通无色实体以T3的13生命为第1日基准。随日期变化见第5节。

### 3.2 Day 2：探索

- 第二天玩家体验目标：探索并找到关于10的线索。
- 时间结束条件：击败掌握线索的Boss——寄生同伴者（HD_20003_1）。击败后开放逆时战场通路并推进至少第3日（B-008）；第2日日内时间归零也会进入第3日。
- 世界变化：方向为地图开始出现少量天人战士，单色实体增多，无色实体减少（见第5节）。

### 3.3 Day 3：反抗与末日临界阶段

- 第三天玩家体验目标：前往逆时战场，完成10剧情并取得首次大战胜利。
- 时间结束条件：最终战正式开战时启动最终战15分钟倒计时，即“暗室侵蚀进入临界状态”，而非普通第三天自然结束。
- 世界变化：方向为地图出现更多空缺与陷阱，敌人增加突进攻击，攻击欲望更强（见第5节）。

临界流程：进入逆时战场 → 10救场（T2第10节）→ 最终战正式开战，进入末日临界阶段 → 在最终战预算内进行救场后的三波协同战斗（T2第11节） → 按战斗结果与时间状态进入阶段结算。救场后的三波协同战斗就是计时的最终战，不是开战前另计的阶段。

**最终战预算**：

- 正式开战时，最终战预算取15分钟与第3日剩余的较小值。
- 暂停、剧情、死亡菜单期间不扣时；死亡与正常读档不回补最终战预算。
- 同帧归零与击杀时胜利优先（A-012）。
- 最终胜利保存后永久开放唯一返回路并停止计时。
- 最终战相关的保存（开战、胜利、对话、结束状态）失败时均保留重试，不提前宣告完成。

取得最后一批敌军清除后的大战胜利，按T0/T2进入胜利剧情与V0.1结束。倒计时归零本身不等于已清除敌军，不自动授予战斗胜利。

## 4. 时间压力与资源刷新

| 设计项 | 冻结规则 |
| --- | --- |
| 是否强制失败 | 不直接Game Over。最终战倒计时耗尽时显示“未来已失”界面，提供重试与返回标题，重试恢复本次开战的最终战预算与所需第3日窗口（原预算为0时只能换槽或新游戏）；第3日正式开战前日内时间耗尽为探索超时，显示独立的探索超时反馈，确认后回检查点并恢复本日30分钟。超时界面由用户于2026-10-19裁决（待决事项总表A-011） |
| 玩家拖延 | 允许玩家反复往返场景击杀重置敌人，以获取足够的可能性进行战斗 |
| 刷怪机制 | 普通敌人重置后仍可再次获得击杀可能性，不设一次性奖励上限；时间推进导致的危险变化沿用原方向：无色实体减少、单色实体增多，非战场区域出现少量天人战士 |
| 时间奖励 | 更早前往后续区域，可遇到更多可帮助NPC与较低敌人难度；未冻结额外货币或数值奖励 |

**超时处理**：

- 探索超时（第3日最终战正式开战前日内时间耗尽）：明确确认后保存并返回当前检查点，恢复本日30分钟；保留当前生命、可能性和永久进度，不补满、不执行死亡扣减，普通敌人重置（T3第10节）。重试的保存失败时继续保持超时状态与0余量。
- 最终战超时（正式开战后最终战预算耗尽）：失败，可明确确认重试：恢复本次开战的最终战预算及所需第3日窗口、重置整场，不重复救场与补满，保持资源与生命；原预算为0时只能换槽或新游戏。若最终战已经开始，不赠送30分钟。
- 超时与结束界面上，Esc与通用继续入口不能绕过明确的重试确认。不做多结局。

快速推进：敌人较弱、可帮助NPC较多，但可能探索不足、资源不足。慢慢探索：可获得更多资源和故事信息，但世界恶化、NPC失救、敌人增强。

“支线更多”在本版仅指已纳入的NPC交互机会，不扩展完整支线系统。普通敌人在往返Room、死亡或正常读档后重置，再次击杀仍发放对应可能性；单个死亡实例不得重复结算。普通敌人收益与NPC一次性事件奖励分开，后者仍不能重复领取（T3第3节）。

## 5. 世界变化

| 设计项 | 冻结方向 |
| --- | --- |
| 环境变化 | 背景随时间变化，后期崩毁、空缺与陷阱增加 |
| NPC变化 | 状态与存活机会受时间影响，可帮助NPC数量减少 |
| 敌人变化 | 攻击欲望、移动与生命、类型构成、数量和攻击方式随阶段变化 |
| 资源变化 | 可通过重置敌人补充可能性；仍受储存上限及获取所需战斗过程约束，计时照常推进 |

时间至少对V0.1流程产生可见影响。变化涉及当前三张地图内的已有内容，不新增后续地图、完整装备、随机战利品或复杂经济系统。

已确定的随日期变化：

- **普通无色实体**：普通探索与营帐围攻的无色单位，第2/3日新生成时生命15/17，移速为基础的110%/120%，攻击间歇（后摇恢复与混合型投掷冷却）为基础的90%/80%；伤害、收益与前摇不变。跨日不修改已生成单位；单色、天人、两场Boss及其杂兵、中心战场配置不变（T2第8.1节）。
- **救助过期**：麦秆镇与沟壑第二、三间的救助可完成至第2日结束，进入第3日立即过期；外围救助在第3日剩余归零时过期。已救助永久保留；过期的救助没有奖励，且与主动放弃是两种独立的情况。这一期限适用于新游戏，以及旧存档中尚未见过的NPC；旧存档首次迁移时，已见过、尚未救助且未主动放弃的NPC永久保留一次救助机会（T3第9节，B-005）。

敌人种类随日期变化与日期地形变体方向已定（A-004、A-005），具体内容待设计稿，见第9节。改变地形后仍需满足T1必经路线不依赖消耗可能性的滑步，以及T3低资源可重新投入战斗的要求；不据此重新引入重复击杀收益次数上限。

实施说明：[日期影响](../game/docs/world_day_rules_implementation.md)、[三日自然计时](../game/docs/day_clock_implementation.md)。

## 6. 剧情时间与玩家认知

- 主角心理变化：第一天轻盈试探并学习生存；第二天发现更多不幸者死亡，随敌人变强而紧张；第三天大范围地图崩毁与场景变化带来紧迫感。
- 玩家认知变化：知道当前时间与世界恶化的关系；在已无法拯救的NPC处，提示更早到来曾有救助机会，让错失机会成为可理解结果。
- NPC记忆：NPC知道时间推进，状态与对话可反映已过去的时间。

7的帮助与成长机制、永久失败确认沿用T3。时间造成的NPC过期与玩家主动放弃是不同触发；对话、剧情与救助放弃确认期间停表，不让对话或剧情暂停造成时间误扣。

## 7. 31天扩展方向（不纳入V0.1制作）

- 完整版时间结构：划分为若干阶段，基础天数依赖游戏内游玩时间，固定关键战斗与NPC交互强制推进日期；与后续存档机制衔接，不在此冻结离线计时规则。
- 扩展变化：更多强敌、解谜与收集品出现或消失、部分Boss演出变化、玩家自身debuff，以及更多规避战斗的手段。它们是完整版本方向，不能据此给V0.1新增Boss或角色debuff。
- 时间与结局：结合友人的注视与初见时间，不同友人随日期变化，过晚可能无法互动，部分友人晚期可能带来反面作用；具体结局分支未在本阶段设计。
- 时间与友人：十二位友人的事件具有时间窗口，但V0.1角色范围仍遵守T0，不制作十二位友人的完整事件。

扩展不应只是“越晚越差”：早期机会多但信息少，晚期更危险但可能获得更多真相、遗物或新的探索机会。评审的Day5/Day20/Day25仅为设计示例，不作为正式日期配置。

## 8. T4设计验收

以下是已确认的设计验收目标，游戏实现后仍须运行验证：

- 时间可感知：玩家通过HUD、环境变化、敌人变化与NPC减少感受到时间压力。
- 时间推动剧情：时间改变NPC存活、地图状态、敌人类型与剧情机会。
- 可扩展性：3天规则可自然扩展为31天阶段系统，不需要本版提前制作完整内容。

后续验证应覆盖自然流逝、关键事件推进、防止日期倒退或重复推进、剧情/菜单暂停、跨日UI、最终战预算、超时与击杀同时发生、敌人重置后重复收益与单次死亡不重复结算，以及时变地形的通行和低资源保障。

本文档测试验证内容覆盖与冻结修订，不代表上述游戏运行验证已经完成。

## 9. 实现前需明确的衔接边界

- 随日期的敌人构成与地形变体：方向已定（A-004、A-005：需要做，排在最后），具体的日期敌人表、强化参数与地形变体待设计稿；本次不擅自新增制作项。
- 世界变化的其他表现：背景随日期崩毁、空缺与陷阱增加等环境变化的具体内容与阈值，随上一项设计稿确定。

这些衔接项需要在对应功能实现验收前明确，不用未确认参数填补冻结记录。T0不做多结局；超时与胜负的V0.1状态映射见第3、4节。不推定退出游戏后的现实时间继续计时。
