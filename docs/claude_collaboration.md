## 一轮工作流程

1. 交接任务卡，写清目标、基线、允许修改的文件、禁止扩大的范围及验收条件。
2. 审查者先读源码和已有测试，给出可定位的发现；只读任务不直接修改工程。
3. 实施者复核每项发现，记录采纳、驳回及证据；已确认缺陷先补回归，再作最小修复。不能复现的发现保留为待验证。
4. 编写或更新相关测试。文档改动执行离线测试与链接校验；运行逻辑改动执行针对性引擎测试和统一引擎验证。涉及操作、画面或手感时补人工验收，不把脚本验证描述为人工通关。
5. 检查 diff，仅暂存本任务文件，通过验证后创建对应 commit；交付 commit、命令结果和剩余限制。
6. 审查者基于新 commit 复核。新发现另开一轮，避免不断扩展原任务。

## 修改隔离与集成

默认同一工作目录串行写入，审查者只读。需要并行时，从双方确认的已提交基线建立独立工作目录与 `codex/` 前缀任务分支，逐项声明文件归属；未提交文件不会自动复制，必须明确是否属于任务输入。

共享入口、存档、玩家控制、场景注册和测试清单由本轮实施负责人统一修改。另一方通过报告提出修改建议。集成前检查依赖及文件重叠；有重叠就逐文件处理，禁止盲目覆盖。只集成双方复核的任务 commit，合并后重跑相应测试；不自动推送、发布或联系外部服务。

## 验证与证据

在仓库根目录运行离线测试：

```powershell
python -X utf8 -m unittest discover -s tests -v
```

Python 环境须包含 `openpyxl`，否则 T6/T7 测试无法载入。本次准备在系统 Python 缺少此依赖后，改用应用内置 Python 执行同一离线套件，2026-10-19 共 72 项通过（含新增 3 项协作资料检查）。本次只新增文档与校验测试，未运行 Godot 动态回归；此结果不代表游戏运行验收。

运行逻辑改动使用仓库要求的 Godot 版本；以下引擎路径由执行者填入实际安装位置：

```powershell
$godotExe = 'C:\实际安装目录\Godot_v4.7.2-stable_win64_console.exe'
python -X utf8 scripts/verify_game.py --godot $godotExe --jobs 4 --report outputs/claude_integration_validation.txt
```

统一入口负责导入、主场景启动及登记的引擎测试。通过需要进程成功、预期测试摘要且无错误或泄漏；不得只查找 `failures=0`。测试组数量以脚本当前清单为准。

`outputs/` 和 `work/` 被 Git 忽略，报告路径只能作为本地证据。跨机器交接时须明确附带报告，或把必要摘要写入随任务提交的实施文档；不能假设接收者能从 commit 取得原始报告。历史通过报告不能替代当前基线的运行结果。
