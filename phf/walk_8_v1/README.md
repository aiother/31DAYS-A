# 初页 · 朝右 8 帧步行 v1

交付采用 **image_gen 内置工具生成的固定栅格部件 + 刚性骨骼绑定，输出 8 张逐帧图**。不在帧间重生成人体，不做网格拉伸或逐帧缩放。头部、衣领和菱形扣保留为同一个固定图层；披风三片、两侧袖子和手、短衣、短裤、左右大腿、小腿、靴子分别绑定。不同部件的初始化尺寸允许不同，但每个部件的尺寸在整个循环内保持不变。

## 左右腿与动态约定

采用 `../步行骨骼图.png` 的明确标记，而非根据脚在画面左边还是右边推断身份：**左腿 L 始终近景，右腿 R 始终远景。** 右腿整条链先绘制，左腿整条链后绘制；交叉和第 5 帧换支撑脚时不交换身份。远景腿使用固定的轻灰阴影，检查版额外显示橙色 L 和蓝色 R；正式素材不带这些彩色标记。

| 帧 | 左腿 L / 近景 | 右腿 R / 远景 |
|---|---|---|
| 01 | 前伸脚跟接触 | 后蹬、脚尖支撑 |
| 02 | 承重下沉 | 离地回收 |
| 03 | 中间支撑 | 从后方经过，脚抬离地面 |
| 04 | 后蹬上升 | 低幅前摆，准备接触 |
| 05 | 后蹬、脚尖支撑 | 前伸脚跟接触 |
| 06 | 离地回收 | 承重下沉 |
| 07 | 从前方经过，脚抬离地面 | 中间支撑 |
| 08 | 低幅前摆，准备衔接 01 | 后蹬上升 |

每条腿跨全部 8 帧完成一个完整周期，左右相差 4 帧。第 5 帧只换承重脚。大腿、小腿的逻辑长度分别固定为 84、86；采用朝前弯曲的膝部逆运动学解。支撑靴按照真实透明轮廓对齐逻辑地面 y=450（输出像素边界 y=901），全部 8 帧保持同一地面线，至少一脚支撑，无腾空跑步帧。角色根位置固定，表现原地步行；实际移动由使用方驱动。

身体每半周期起伏一次；两臂与腿反向摆动；披风三片以延迟的小幅旋转跟随。头脸、单根呆毛、翻领、菱形扣保持结构，随躯干起伏。统一画幅和统一部件比例，画面轮廓宽度随动作自然变化。8→1 也纳入关节位移和循环回放检查。

## 素材来源与处理

读取项目 `phf` 下的全部 5 张参考：`原案v0.1.png`、`三视图_1.png`、`三视图_2.png`、`部件_1.png`、`步行骨骼图.png`。采用朝右的侧面造型和原骨骼明确的近左、远右约定。

使用 **image_gen 内置工具**，没有调用 API/CLI 替代。最初整张生成的步行草案不能稳定保持腿部身份，未作为最终动画使用；只抽取其中固定的头部、衣领、菱形扣形象。部件图集由 image_gen 根据 `部件_1.png` 提取。随后一次性切片、提取领口边界、清除透明蒙版中的游离噪点，并裁去供绑定用的接头示意端帽；渲染器以固定栅格部件作刚性旋转和平移。近景白、远景灰的阴影系数在帧间固定。PNG/APNG 保留完整透明度，GIF 使用统一调色板和统一灰底。

这是固定部件驱动的逐帧输出；并非每帧独立重新手绘。自动检查可以约束部件绑定、比例、层级、地面、轨迹和编码一致性；服装自然程度与形象接近度还需要结合检查图和循环观看判断，不能仅凭测试通过推导。

## 复现与验证

依赖 Node.js + `@napi-rs/canvas`、Python + Pillow。Node 包目录可通过 `CODEX_NODE_MODULES` 指定；默认使用当前 Codex 捆绑运行时。无需重新生成图片或联网。

```powershell
node scripts/render_phf_walk.cjs
python scripts/build_phf_walk.py package
python -m unittest discover -s tests -p test_phf_walk.py -v
node tests/test_phf_preview.cjs
```

实际用例直接核对渲染器输出的部件变换和 PNG 像素：左右腿完整相位、固定遮挡和资源身份、恒定骨长与部件缩放、步态轨迹及 8→1 位移、脚底同一地面、头部像素仅随预定起伏平移、衣物/手臂摆动、无损 APNG 逐帧一致、GIF 帧数和时长、透明画幅与序列图逐像素一致、原始参考及交付文件哈希。交付目录中的 JSON、HTML、Markdown 固定 LF 换行，避免 Windows 重新检出后文本字节变化导致哈希失效。检查器另有播放、暂停、单步、跳帧、速度、标记开关和键盘测试。
