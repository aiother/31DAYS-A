# 敌人受击与动作打断修订

2026-10-16，制作人要求：敌人的重攻击、闪避、防御、弹反不被玩家攻击打断，同时预留后续失衡值打断扩展。本次不实现失衡条、积累值、阈值或恢复规则，不新增地图或敌人能力。

## 当前行为

- 单色实体的强力攻击、天人的重击：前摇、判定与后摇都不因普通命中转为受击硬直，不改变动作计时、方向、速度或攻击名额；玩家攻击起手也不能令强力前摇自行取消成闪避。后摇仍可造成生命伤害。
- 单色闪避保持已有无敌窗口，普通打断请求不能取消闪避。
- 天人防御与格挡后的待反击、反击前摇/判定/后摇不中断。首次正面格挡仍阻挡伤害；之后命中或上下/背后攻击可按原规则扣血，但不会清除当前防御或反击链。等待反击仍受原有效期和攻击名额约束，不立即抢攻。
- 正常命中保留扣血及闪光反馈；不中断不等于额外无敌。保护动作期间不施加会改变动作轨迹的击退。普通轻攻击与其他原有可打断状态仍受击硬直、击退并释放攻击名额。普通冲刺及用于换位的瞬移预警保持原规则。
- 致死优先：重击、防御或反击中生命归零，仍立即死亡、清理动作并结算一次奖励。两只Boss原本命中不打断行动，继续保持原行为。

## 扩展接口

ColorlessEntity的生命扣减与动作中断分开：先结算伤害/死亡，再调用request_interrupt。普通命中只使用InterruptReason.HIT；_protected_action由单色/天人状态机判断。

未来失衡组件达到阈值后，可显式调用request_interrupt(InterruptReason.STAGGER, impulse, duration)。该原因允许打断保护动作，进入指定时长STUN，并通过_interrupt_action钩子清理闪避无敌、运动、待反击及攻击名额。死亡对象拒绝请求，接口不修改生命、资源或奖励。当前没有任何玩家攻击自动提交STAGGER，也没有实际失衡数值系统。新普通敌人可覆写保护动作和清理钩子；独立Boss状态机的失衡响应留待其正式规则确定后接入。
