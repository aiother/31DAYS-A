## 试玩

F5进入 `debug/checkpoint_lab.tscn`。选择三个槽之一的新游戏并确认，或继续已有槽。新游戏仅覆盖所选槽；空槽不显示继续，损坏/不兼容槽显示不可读取。Esc可继续、设置、选择存档槽或确认保存并退出。窗口关闭同样先确认；写盘失败留在菜单并显示错误。

测试场地有两面旗：起始检查点 `(224,896)`、前方检查点 `(608,896)`。进入范围自动记录最后检查点，不补生命、不补可能性、不刷新敌人。旗帜为本阶段开发夹具，ID为 `graybox_start/graybox_forward`；未冒用T5正式Node编号或宣称已放置8个正式检查点。范围/位置通过 `CheckpointConfig` Resource配置，后续随正式Room替换。

## 保存与恢复

- 本地JSON存档版本1，三个独立槽；位于Godot `user://saves/slot_1.json` 至 `slot_3.json`。Windows通常在 `%APPDATA%/Godot/app_userdata/末日前31天 · V0.1 玩家灰盒/saves/`，以Godot“打开用户数据文件夹”为准。存档不包含在工程包。
- 保存当前HP、可能性、上限10、最近检查点ID、永久事件标志和累计试玩时长。不会保存攻击/滑步/恢复计时、当前坐标快照、普通敌人或投掷物。
- 自动保存时机：新游戏、检查点切换、资源变化、永久事件写入、死亡结算、槽选择与正常退出。事件接口仅为持久化契约，不代表NPC、成长、物品、日期或最终战系统已实现。
- 正常退出再继续：保留最新生命、可能性及负余额，在最近检查点出现；普通敌人重置，无复活无敌。当前坐标不回放。退出不执行死亡损失。
- 死亡：资源结算在HP归零时只提交一次，防止退出重进逃避损失；满生命5，非负可能性保留50%，**按本日用户确认向下取整**（3→1、5→2、9→4），负数清零。死亡菜单等待和重复受击不再次扣除。倒地/转黑完成后，从检查点继续会重载敌人，保留永久事件，并给予3秒保护，攻击不解除。
- 如果在死亡菜单退出，再从槽继续，会载入已提交的满血/损失后余额；按正常载入规则不额外发放3秒保护，也不重复扣费。
- R在存档主场景只提示从存档槽确认新游戏，避免开发重置误改进度。原 `enemy_lab.tscn` 等独立开发场景保留无存档的R重置/出生点重试。

## 文件可靠性与边界

仅解析JSON，检查版本、检查点白名单、整数资源范围及标志类型，不从存档加载脚本/Resource/场景路径。写入临时文件、刷新并校验后轮换主文件和上一份有效 `.bak`；主文件不可用则尝试备份并提示。两份均不可用时保留文件，需玩家明确确认新游戏才能覆盖；不静默创建新进度。不能承诺断电时操作系统或硬件尚未持久落盘的数据不丢失。

当前版本仅接受当前已实现的上限10、灰盒检查点和存储字段。没有用空字段宣称日期、成长、道具、任务系统完成；将来引入正式Room或新增版本时需提供明确迁移。设置仍仅当前进程生效，未加入设置存档。

读档传送后会核对触发器与玩家当前实体位置，防止物理队列中的旧进入事件将刚载入的前方检查点覆盖成起点。测试保留此回归。
