# 正式暂停菜单与保存反馈（UI-003）

用户选定的方案落地：交互为 EXP-001 方案四，视觉为 EXP-002 样张二，样式来自 UI-001 的 `game/ui/style/`。替换此前的灰盒暂停面板；死亡菜单、存档槽界面、最终战超时与结束面板仍为灰盒（第五批）。

## 结构

- `game/ui/menus/pause_menu.gd`（`PauseMenu`）：左侧纸面上是选项；右侧默认画时钟，二级界面（设置、保存并退出确认）打开时盖住时钟。只负责排版、绘制与焦点，动作都回调 LifeUI。每帧写入 `drawn`（实际绘制记录）供测试读取。
- `game/ui/menus/ink_button.gd`（`InkButton`）：墨线按钮，焦点为手绘下划线加朱红小三角（UI-001 主题约定由界面自己画焦点）。
- `game/ui/menus/save_toast.gd`（`SaveToast`）：“检查点已保存”小纸签，2.4 秒后淡出，放在 LifeUI 状态列里、操作提示之下，不压住 HUD 与错误提示。
- `game/ui/menus/life_ui.gd`：`show_pause`、`show_settings`、`confirm_quit`、`resume_game` 等公开方法不变，内部改为驱动 `PauseMenu`；其他灰盒面板打开时会先关掉暂停菜单。`_quit_handler` 默认是 `get_tree().quit`，测试可替换以验证“保存并退出”而不结束进程。
- `game/debug/checkpoint_lab.gd`：新增 `checkpoint_saved(id)` 信号（用户 2026-10-21 同意由 Claude 顺手加、Codex 审查）。在 `save_current()` 成功写盘、且写入的检查点与上次落盘的不同时发出；读档时记下当前检查点。周期性、资源、事件自动保存，读档和写盘失败都不发。集中在 `save_current()` 判断，覆盖营帐、沟壑、堑壕第二间这三处自己处理检查点的子类。

## 选项与页面

| 选项 | 行为 |
| --- | --- |
| 继续游戏 | 关闭菜单，恢复计时 |
| 设置 | 二级页：音量、窗口尺寸、全屏（沿用现有三项，换正式样式）；新设置项在第五批接 SYS-007 |
| 存档槽 | 仅会话支持存档槽时出现；打开灰盒存档槽界面（主界面完成前暂留，用户 2026-10-21） |
| 保存并退出 | 二级页确认，默认焦点在“返回”；确认后保存并退出游戏，下次从最近检查点继续；写盘失败不退出，页面显示错误原文（暂停纸面盖住了 LifeUI 原有的错误提示） |

没有存档能力的开发场景，最后一项为“退出游戏”。

右侧时钟：时刻与 HUD 地平线纸签使用同一换算（`FormalHud.clock_text`）；第N日与末日倒数；三天进度（之前的日子满格，当天按日内进度）；下一行为“距下一日 mm:ss”，第三日为“最后一日”，最终战中为“最终战剩余 mm:ss”（真实预算）；再下一行为会话 `quest_status_text()` 的当前任务，为空时不显示。没有会话时间的开发场景不画时钟。

## 输入

方向键 / 手柄十字键移动焦点，Enter / Space / 小键盘 Enter / 手柄 A 确认，鼠标悬停与点击。Esc / Start：时钟页关闭菜单；二级页返回时钟，焦点回到打开它的那一项（原型行为；此前灰盒返回后焦点在“继续游戏”）。

## 测试

- `tests/test_pause_menu.gd`（41 项）：真实 Esc 打开；时钟时刻、日期、三天进度、距下一日与 `ui_time_state()` 一致；暂停 60 帧计时不走；方向键、十字键、鼠标、Enter 操作；二级页盖住时钟、Esc 返回并恢复焦点；保存并退出先确认、失败不退出并显示错误、成功写盘后只退出一次；周期保存不提示、检查点写盘失败不提示、进入沟壑的真实检查点成功后提示并淡出；两种分辨率下保存提示不压 HUD 与错误提示，暂停纸面、时钟、二级页都在窗口内且互不重叠；最终战暂停显示真实剩余、前两日满格、当前任务与会话一致。
- `tests/test_pause_acceptance.gd`：通过 ENV-006 启动器跑 UI-003 验收适配的自测，并确认临时存档被清理。
- 变异：二级页不盖住时钟、暂停时计时继续、保存失败仍退出、保存失败也提示，均有测试失败。
