# SYS-002：残存可能性实体

依据：T3 §11、待决事项总表 A-002 与用户批准的 SYS-002 任务卡（含灰盒初值）。本记录描述实现，不增加策划规则。

## 接入与隔离

`BossSession._bind_room()` 在原绑定之后调用 `RemnantPossibilitySpawner.attach()`；后续 session 通过继承复用这一入口。组件只接入 CampWavesRoom、BossRoom、ParasiteRoom、RescueBattlefieldRoom（包括 FinalBattlefieldRoom），重复绑定不重复创建。正式 FinalBattleSession 因而覆盖营帐围攻、渴望俯视、寄生同伴者、中心战场救场前战斗、救场后最终战五场战斗；两间堑壕和其他房间没有生成器。

组件是当前 Room 下独立的 `RemnantPossibility` 容器。生成实体不进入 `Enemies`、`OrdinaryEnemies` 或 `Allies`，不参与波次/胜利判断，不进入友军目标列表，不占普通召唤/支援名额，也不取得 EnemyAttackCoordinator 进攻名额。普通无色实体及两个 Boss 的既有支援代码、数量、属性不变。

`RemnantPossibilityEntity` 继承 ColorlessEntity，继承场景保留实际受击区域和无色实体表现；覆盖物理处理，只做缓慢漂移，不调用普通 AI 的攻击/投射物/追击。每个实体复制自己的 ColorlessConfig，生命13、奖励+2、伤害0，飞行模式，没有日期缩放，也不修改共享普通敌人 Resource。

## 计时和生成

配置入口：`game/data/enemies/remnant_possibility.tres`（RemnantPossibilityConfig）。默认间隔10～15秒、单批随机1～2个、同时最多3只；高度160～240、水平±240、生命13、奖励2均为任务卡批准值。漂移速度24、振幅(24,12)、位置抽样次数32是可调实现参数，不改动已有战斗数值。

使用整数比较 `balance * 2 < maximum`，支持负数及成长后的奇数上限，不把50%向下取整。当条件成立时采样10～15秒倒计时，满额时本次不生成；下一周期继续采样。余额不低于一半时重置计时，已在场实体保留，重新低于一半后从新周期开始。每次最多生成剩余名额数，不补发大 delta 内错过的多个批次。

候选位置在玩家上方的批准范围内随机抽样，整个80高/48宽的身体须在 Room bounds 内；使用胶囊形状查询世界、玩家和敌人实体碰撞。当前批次及已有保底实体再直接检查身体矩形，避免同帧新身体尚未同步到物理空间造成重叠。32次仍无合法位置时放弃该只，等下一周期再试，不将实体塞入墙内或移动到批准范围外。生成后通过物理移动漂移并受房间边界约束。

## 生命周期与资源

- 营帐在 READY 前不计时，围攻期间（含波间）启用，COMPLETE 清理；Boss 在 WAITING 时不计时，进入战斗后启用，DEAD/已开启通路时清理。
- 中心战场只在实际开始、未停止/完成的 OPENING/COOP 阶段启用；救场过场结束首段战斗时清理。最终战波间预警保持同一场战斗，最终胜利清理。
- 组件以 ALWAYS 模式观察结束状态，但树暂停、剧情控制锁、intro、对话/确认、加载/重载/切房期间不扣倒计时；已在场实体停止漂移和受击。实体自身为 PAUSABLE。暂停不造成解暂停瞬间补发。
- 玩家 died 信号立即清理；Room 离树也清理。清理只关掉受击、移出容器并释放，不发 defeated 信号，不奖励。死亡菜单无法生成；读档/重进只重建瞬态组件，不保存实体或倒计时，不增加存档字段。
- 正常击杀沿用 ColorlessEntity 的死亡单次信号，通过 session 原有 `_on_room_enemy_defeated` 路径调用 PlayerPossibility.gain：+2、当前上限截断、负余额偿还及已有自动保存全部复用。死亡或结束时不再支付奖励。没有新增奖励或保存规则。

## 验证与 G4

`game/tests/test_remnant_possibility.gd` 已登记到原验证器。测试使用独立存档目录及真实 FinalBattleSession 房间，覆盖五场战斗接入、阈值/成长上限/负数、间隔及上限、碰撞与批次重叠、真实四方向攻击、暂停剧情、原波次/召唤物隔离、死亡/胜利/离开/正常读档清理。确定性边界用手动推进组件时钟验证，另用真实物理帧验证自动生成，不以测试直接调用替代全部运行接入。

任务交付前运行 G1 以及完整 G2＋G3，实际 SHA、计数与日志哈希记在 delivery.md。G4 仍由用户在 Claude 审查通过后，进入至少一场强制战斗将余额耗到一半以下，观察10～15秒生成、击杀+2、在场上限3、回升后停止新生成；自动测试不代替实机观察。
