# 高级追击AI可靠性基线（2026-10-18，bug4）

本轮按用户要求检查全部已交付场景和节点位置的高级追击。对象为已发现目标的地面单色实体、天人战士，以及Boss战中的飞行单色实体。没有新增地图、敌种或奖励。

## 这次处理的根因

bug4中敌人站在沟壑入口矮台顶，玩家移到右侧连续平台后，敌人长时间不接近。前几轮局部方案缺少近同高平台的连续路线，也不能可靠处理先离开当前平台、再从另一段地面登高的情况。全Room审计进一步发现：一整条同高地面被关闭的门切开时，目标选择仍可能将门另一侧的起点误认为已到达目标区域。

`EnemyPlatformRoutes`从实际TileMap与StaticBody碰撞构建当前Room的有向路线。可站立点包含表面两端、中心、每64像素样点，以及场景出入口、检查点和交互Node的横坐标投影；每个点仍需要实体净空与三点平整支撑。边分为连续地面步行、完整碰撞验证的跳跃、自然走出边缘后安全下落。目的地使用玩家所在位置最近的安全点，不能再将被墙分隔的整条同高地面视为同一个已到达区域。

普通局部追击保留用于快速响应；缺少有效路线约0.25秒或追击实际无位移进展约0.65秒时进入多跳规划。规划结果逐段执行，起跳前再检查碰撞，落地后检查是否到达预期落点。目标换层/大幅移动、平台增减、身体所在Room改变、跳跃/速度/落差参数改变都会重新检查或规划。执行失败的边短暂避让并重算，避免持续撞同一个位置。暂停冻结路线与恢复计时；正常受击、失衡、目标死亡或丢失会取消旧路线，交还既有战斗状态机。

## 动作和不可达处理

跨台跳跃的垂直初速仍为现有950；普通地面移动仍为单色240、天人300。为了跨过当前地图中宽于普通跑跳覆盖的间隙，路线跳跃水平速度允许使用各自已有冲刺上限480/600；不瞬移，不穿墙，不增加无敌，不改变生命、伤害、收益、起跳冷却、下落上限或受击/重击保护。原T1/T2玩家手感与Spine视觉边界不变。

暂时无路线时不会保留永远等待的旧起跳指令：先接近当前可达的安全位置，在有视线且现有射程允许时使用已有可弹反投射物施压；没有可用攻击条件时继续安全搜索/换位并定期重算。射击继续使用原伤害、前后摇与共享攻击名额；不隔墙射击，不改变关闭通路、不跳入无落点断崖。真正没有合法移动空间时可以保持安全站位，但决策仍更新，玩家回到可达位置后必须恢复追击/战斗。

路线缓存按Room实例和移动参数共享，Room退出时释放；几何约每0.5秒复查。碰撞边验证分帧执行，同一图每物理帧共享约1.8毫秒验证预算，避免多名敌人重复完整构图。新生成的平台纳入后续缓存；旧路径仍受实时碰撞与进展检查约束。

飞行单色使用`EnemyAirPursuit`：32像素二维净空网格依据角色完整碰撞体检测，沿安全格点绕开实心平台，逐段再验证身体扫掠；进入既有射程且具有视线后交还原战斗状态机。不会因为躯干射线短暂恢复就中断尚未完成的绕障路线，避免在同一平台边缘往复。无进展会避开失效格点并重算；暂停、受击、目标丢失、目标移动及几何改变都有对应退出或刷新。速度、投射物参数、共享攻击名额不变，不穿墙。普通无色飞行支援沿用原行为，本轮高级飞行对象为单色实体。

## 验收方式

`test_pursuit_recovery.gd`覆盖视频三层平台、主动注入无进展路线、空中不可达目标远程压迫、玩家回地面、跳跃中真实受击、暂停、目标丢失/重新出现，以及平台新增后的缓存失效。旧bug2/bug3、上下行、墙和断崖、动作保护、攻击名额、Boss、连续主线全部保留回归。

`test_air_pursuit.gd`在同样24种布局中执行108次飞行单色的真实身体移动：平台上下双向、连通区域极远位置；另有6项动态检查，覆盖实际开始绕障、暂停、真实受击、平台增添、目标丢失和移动后恢复攻击。对应原始报告为`pursuit_air.json`，与地面路线矩阵分开统计。

`pursuit_survey.gd`及A/B/C/D/E五个入口覆盖18个Room和六个额外阶段布局：渴望俯视平台出现前后、最终战临时平台、围攻开门、堑壕返回/碎石堆开路及最终胜利开门，共24种布局。每个采样点的全部有向位置组合做连通检查；每个具备可达路径的点，都作为实际物理追击起点和终点执行最远对应点模拟，去除重复组合。每个存在不可达目标的起点额外检查决策保持及目标返回后的恢复。可达案例必须实际进入目标表面并接敌或开始有效攻击；追击状态无进展超过120个60Hz帧即失败，正常攻击前后摇、起跳冷却和受击硬直不作为AI僵直。

大规模模拟使用固定60Hz物理步长加速墙钟运行；原53组普通回归继续按原实时方式运行。报告严格分开规划组合与物理实跑，不将有限样点表述为穷尽所有连续坐标、输入时序或未来地图。新增场景、移动参数或碰撞资源改动后须重新运行，保持无失效路线卡死这一验收门槛。

执行：`python scripts/verify_game.py --godot work/engine/Godot_v4.7.2-stable_win64_console.exe --jobs 4`，然后`python scripts/summarize_pursuit_survey.py`。原始五份矩阵JSON与角点JSON、位置CSV、点对CSV和《追击AI全场景审计.md》生成在仓库outputs；压缩包的verification目录携带报告与校验摘要。打包会拒绝缺少节点起终点覆盖、缺少不可达恢复、存在失败或不完整的引擎验证报告。


额外的`test_pursuit_contacts.gd`逐一扰动全部布局中合法平台的两端圆角接触。小跳重新落稳或安全下撤均使用完整碰撞轨迹；不能把胶囊角点误判为完整平面，也不会因初始边缘侧探针落空而拒绝向内走。起点最初32像素允许中心支撑过渡，完整身体扫掠仍有效，之后及落点保持原支撑规则；向断崖移动仍会失败。
