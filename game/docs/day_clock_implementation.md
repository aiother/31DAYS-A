# 三日自然计时与超时重试（2026-10-18，用户确认）

## 本轮范围与规则

主入口`world/final_battle_session.tscn`接入完整三日自然时钟。每天30分钟，按游戏物理时间推进，不读取现实时间戳、不计算离线时长。日期从1递增到3；第一日耗尽进入第二日、第二日耗尽进入第三日。跨日显示画面中上部日期提示；日常时间由正式 HUD 的底部地平线与右下日期显示（UI-002，见formal_hud_implementation.md），替代原先右侧的日期分秒文字；敌人首见卡片仍不暂停普通战斗时间。

剧情推进调用`DayClock.advance_to`，只取更晚日期：7首见完成后抵达沟壑入口至少第2日，寄生同伴者胜利至少第3日。只有实际跨日才初始化新一天；自然日期已经到达或超过事件日期时，重复检查点、迟到的Boss胜利、往返与读档都不补时、不倒退。大步长跨日保留多余时间，第三日余量交给原`FinalClock`单独消耗，防止双扣。

菜单、设置、选槽、对话（包括普通重复对话）、救助放弃确认、首次剧情/演出、死亡动画和死亡菜单均停表。暂停用SceneTree与显式守卫双重检查。普通战斗与敌人首见介绍照常计时；保存/载入和Room切换中的短暂控制流程不推进。

自然时间不自动标记NPC死亡/失救，不生成额外敌人，不暗改生命、伤害或AI参数。NPC窗口和随日强化仍需具体规则；已确认的主动放弃、救助成长及既有战斗配置保持原规则。

## 第三日与最终战

尚未正式启动最终战时，第三日耗尽进入“第三日时间已耗尽”界面并暂停世界。不会虚构救场、最终战开战或胜利事件。确认重试后，保存本日30分钟与清除探索超时标记，重载当前已保存检查点；保持当前生命、可能性和永久进度，普通敌人重置，不补满资源、不提供死亡复活奖励。保存失败保持零剩余、超时界面与原数据，允许再次明确确认。

一旦最终战已经启动，即使死亡/读档后暂时回到检查点，也继续使用已确认的最终战规则：开战预算取15分钟和第三日剩余的较小值，普通死亡/读档不回补，超时仅能恢复本次原预算；不改成30分钟重试。最后一击与归零仍超时优先。最终胜利后停止时间；结束状态保存与正常读档照旧。

超时和结束界面拦截Esc；通用“继续游戏”同样不能解除超时暂停。保存退出、选槽与新游戏继续可用，读入超时槽仍显示超时，必须明确选择重试。

## 数据与保存

配置为`data/world/day_clock.tres` / `DayClockConfig`：每日1800秒、计时快照间隔0.5秒、日期提示4秒。`DayClock`处理前两日及事件跨日，`FinalClock`保留第三日和最终战的单一计时入口。

存档仍是版本1，新增可选`day_remaining`（当前第一/二日余量），第三日继续使用`day3_remaining`。旧第一/二日档从采用本轮版本时给当前日30分钟，不倒推`play_seconds`；旧第三日与最终战余量原样保留。所有时钟必须是有限非负数且不超过对应预算，布尔、字符串、空值、NaN和无穷均拒绝。`clock:day3_timeout`只能在第三日剩余为0且最终战未启动/未胜利时存在，不能与最终战超时混用。

每0.5秒、日期跨越、资源变化、检查点、死亡、正常打开选槽和保存退出都沿用生产保存流程落盘。自然日期已发生但写盘失败时保留运行中的实际时间与错误提示，后续重试保存；不因失败返还已经消费的时间。剧情跨日与其检查点/Boss奖励同一事务，失败回滚日期及余量。正常读档和死亡续时不回补；强制结束进程只能恢复最后成功写入的快照，备份仍按既有损坏恢复策略保留。
